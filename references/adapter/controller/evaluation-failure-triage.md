# Controller 评估故障分诊与证据采信

> 状态：ACTIVE。用途：使用本渠道时处理拒收、构建／验证异常、无效观察和比较疑点。只规定转换方如何消费现有接口，不声明 Controller／VM Agent 已实现新诊断功能，不新增 schema、状态机、脚本或比较器。

冻结／版本按[任务状态](../../framework/task-state-contract.md)，构建条件按[构建前提](../../workflow/build-prerequisites.md)，观察与 oracle 按[评估准备](../../framework/evaluation-readiness-contract.md)。取证、未知提交与清理按[当前协议](platform-revision-adapter.md)及[连接适配](remote-controller-adapter.md)。本页不授权执行样本、部署、联网、造驱动或修改原判。

## 1. 在既有记录中分开保存事实、责任和去向

发生问题时，先回读本次精确 job／attempt、源／目标字节、请求／输入／命令／实际平台身份及适用原件。在既有 attempt、result.md 或批次问题记录中关联下列内容，不再创建一套平台字段或强制逐项独立报告：

| 内容 | 记录要求 |
|---|---|
| 原事实 | HTTP／传输、jobKind/mode、阶段、build/execution 状态、真实退出码／超时及原诊断；原 report/comparison 标签不改写 |
| 观察采信 | 本次确实检查／运行了哪份文件、输入是否送达、输出属于程序还是装置、是否截断；依据不足写具体未知，不从总标签填 PASS |
| 责任与依据 | 目标代码、源自身、提交／工程配置、工具链／环境、评估装置或比较策略；可并存，未定位不凭猜测归因 |
| 处置与范围 | 实际修改对象／父版本、受影响证据、适用修复计数、已验证／未验证范围、下一步及原件指针；生命周期仍由原契约决定 |

同一目标漏分隔符同时被归一化掩盖时，分别记代码差异和策略问题，不把两层问题统计成两个任务；不把平台 semantic_pass 改写为 mismatched。真实源码错误也不因工具链更严格而自动变成纯环境故障。

## 2. 逐阶段定位，避免把准备缺陷算作代码失败

下面是按已发生事实选择的分诊引导，不要求每项执行所有实验或反复重提。先核打包／身份与构建配置，再核阶段超时、工具链、命令传递和依赖；有直接根因证据时不为走表而追加无关动作。

| 现象 | 先核原件和事实 | 消费与处置 |
|---|---|---|
| 403 identity_mismatch／输入文件不存在 | 分类准入的 case、方向、完整 source/ 路径与字节集合；manifest／表单身份；相对路径的实际基准 | 区分缺／多／内容变更和字段错位，按[分类准入](../../workflow/classifier-agent-gate.md)处理；不靠删驱动、只比较主文件或反复试别名过关 |
| 归档或解包错误 | 原 ZIP 条目名、根布局、重复／越界路径及精确提交集合 | 按连接适配的 ZIP 规则；反斜杠归档未经拒收实测不能报告为平台已发生故障 |
| build 失败、exitCode=null 且 command timed out | manifest/profile 请求、实际限制／持续时间、调用／终止与清理；是否有编译器的确定错误 | 按构建前提 §4.3，记录构建超时，不单由该事实判 SOURCE_NOT_BUILDABLE；旧诊断保留，不能靠任意改大超时无限重投 |
| 同 OS 源链接失败或声明不可见 | 编译器家族／版本、架构／ABI、SDK／链接器、方言、实际导出和诊断位置 | Windows 不保证 MSVC 内建可由 MinGW 支持；只给本候选结论。警告降级条件消费构建前提 §4.1.1，不套普遍宏替换或放宽选项 |
| CS5001 但文本中存在 Main | 精确工程／Compile 输入、输出与排除路径、SDK、入口形态及实际命令 | 构建前提 §2.2；诊断不等于源没有 Main。优先现有默认输出及精确启动路径；不生成复制钩子、入口或桩来补装置 |
| 解析返回 0，但变量／引号丢失、只打印命令或检查文件不符 | 冻结命令、实际请求、合法解析入口／版本、原始构建流、文件身份及已提供的执行资料 | 依连接适配核命令传递与错误集合；有空跑证据时本侧语法 UNVERIFIED，原 passed 保留。成功解析可无输出，不强求固定标记 |
| 语法通过但 require/import、程序集加载或宿主启动失败 | 实际失败阶段、精确依赖／包上下文／工程、合法入口与诊断 | 语法证据保留，加载／启动／业务覆盖另列；缺同包源／框架不伪造，缺 main／驱动按既有 LIB 规则，不把加载当“不运行的解析” |
| evidence 已 200，report 404 或状态为 CLEANING | kind/mode、调用阶段、各适用件响应及 closure/cleanup | 当前协议 §4 按件取证。早期可见不证明终态；404 不单独证明 job 不存在、失败或未执行，未知提交／清理仍 WAITING |
| codeVerdict=inconclusive 或其他总标签 | 实际逐侧 buildAssessment、build 诊断／退出和 execution | 编译层从有效构建原件定案；功能未评估不抹去编译失败，也不把总标签当编译 PASS |
| baselineAssessment=UNVERIFIED | profile 版本、reasons、独立 functionalProfile 的提供／支持／消费与实际源观察 | 缺独立 oracle 不等于装置失败或源执行失败；有效冻结期望及真实源观察可支持有限基线，仍按评估准备核有效性；不伪填平台 PASS |
| minor／semantic_pass 与原始路径或关键值冲突 | 原始流／structuredValue／副作用、归一化配置和规则、冻结允许关系／保护项 | 按[比较策略](comparison-policy-adapter.md)复核；配置不能覆盖业务相对路径、固定端点或数值。已定位误译照现有有限反馈处理；原 verdict 保留 |

平台本来未支持某种工具链／依赖，与本次提交者误选工具链或漏配链接库分别说明；两者可有关联但不是同一责任。静态特征只用于候选能力提示，不能替代真实可构建诊断。报告引用旧批次事件时注明版本／证据层级，不能从历史报告直接宣布当前部署仍有该缺陷。

## 3. 对解析有效性疑点的有限核验

优先回读已有精确执行资料，不把阴性对照设为每个任务必经步骤。实际入口／传输链有效性仍存疑时，可交获批平台维护侧使用合法提供的无害有效／无效语法文本，在同一工具链、入口、文件消费及命令传递条件下只改变语法有效性，验证错误集合及失败退出确实生效。对照只证明该检查链，不证明被转换程序的业务等价。

Agent 不生成坏样本、解析脚本、包装驱动，也不修改交付目标做对照；已有报告的历史对照不自动成为当前入口的证明。-EncodedCommand 只解决特定文本传输形态，-c／-m 或 Base64 token 本身不是执行有效性保证；正文须合法、精确且按原协议消费。缺相关能力记缺口，正常成功检查不因没有对照而一律无效。

## 4. 配置修正、重提和预算

只改超时、命令传输、工程输出或请求身份且未改目标代码时，记录实际配置修正，不虚报模型代码修复；也不能因改了配置就自动免去受影响的源基线／分类／目标验证。条件变化按任务状态关联，重提交用当前协议的 submissionId 规则；未知原提交不能借新 ID 盲重投。

已确认属于转换引入的代码／目标内容缺陷，按[单项闭环](../../workflow/conversion-evaluation-loop.md)的实际修复预算处理；生成目标的注释包含意外终止符而形成语法错误，也属于目标缺陷。新 run、平台归因或功能 oracle 缺口均不重置同一问题预算。清理未知始终按原契约保持 WAITING；仅档案或比较疑点不自动证明有活动进程，去向按真实证据决定。

## 5. 平台维护与交接内容

维护建议可包括字段级拒收原因、有效命令传递与文件消费记录、阶段超时来源、逐件就绪、归一化前后差异及规则范围、独立断言未提供／不支持／失败的区分。它们不是新 capsule 字段或现役能力承诺。现有接口没有的资料明确记未提供，不访问安装目录/jobs 或借未授权部署来取代合法接口。管理者可独立授权智能体执行维护，无须由管理者亲自操作；实际恢复路径和权限条件见 §6。

交接使用精确实现／契约身份、脱敏诊断、最小有区分力的合法场景和应保护的失败条件；密钥、源全文、敏感载荷不因“回显命令”进入日志或报告。维护方改变产品或配置后按原发布／恢复约束复验；旧证据与原判不追改。本仓库文档修订及文字走查不算平台动态修复通过。

## 6. Controller busy、孤立作业及维护恢复

最新候选续轮在[协议 §6.2](platform-revision-adapter.md#62-2026-10-20-续轮开发收口仍须核实际部署)补齐原始流、固定平台解析见证、oracle 消费索引、供应目录和加载诊断。BUILD_VALIDATION_INVALID 是平台语法见证未建立，不把 shell 0 当语法 PASS，也不直接归于目标转换错误。依赖／加载的 REPORTED 签名只给阶段线索，责任仍据原 stderr、精确源／目标和条件归因；不自动修代码、补桩或放宽编译器。旧原判不因源码升级重写。

LEGACY_POWERSHELL_PARSER_UNVERIFIED 同样表示已识别旧式解析命令缺文件消费依据，真实 build.completed/0 原件仍保留，独立语法判读 inconclusive。不能当成源不可构建或模型修复反馈；按已支持平台验证方式和冻结变体处理，未知执行／清理仍沿原 WAITING 门禁。

2026-10-20 候选源码已开始实现准入差集／UTC、阶段预算、逐件就绪与 v3 路径保护，协议与未部署条件见[当前适配 §6.1](platform-revision-adapter.md#61-2026-10-20-候选协议扩展部署后条件消费)。尚未部署的能力不参与现役判读；命令摘要仍不证明文件消费，程序原字节／来源认证、离线供给和分类器变更未因此完成。

Controller 的故障恢复按[作业恢复适配](controller-job-recovery-adapter.md)执行，不止停留在“交给管理员”。先保留精确 job／submissionId 和真实状态／清理证据，区分活动执行、未知提交、历史 closure 阻塞及服务不可达；未决执行不因重启、READY 或健康成功解除。

具有管理者适用维护授权且部署支持时，智能体可使用受保护执行通道查询 blockers／plan，按 releaseEligible 或 recoveryEligible 选择 release-cleaned／restore-and-release，保留 operation 并核 SUCCEEDED、cleanupConfirmed、schedulingReleased 与剩余 blockers。已有授权覆盖时直接沿用，不为每一步重复确认。授权须覆盖实际 VM scope；缺条件、过期审阅、活动互斥或恢复失败按适配中的停止／重查路径处理，不盲目重投、删 jobs 或改原判。

只有不能在现有权限／接口／部署范围内安全恢复的部分才形成明确交接。调度恢复与旧项交付／功能／终态分开；新评估另记 attempt 并核冻结、准入及隔离，不借恢复回放旧 submissionId。
