# 转换任务身份、冻结与状态契约

本页规定任务记录的语义，不新增 Controller schema。由[根入口](../../SKILL.md)、[单项闭环](../workflow/conversion-evaluation-loop.md)、批次工作流和交付契约消费。执行红线以[安全边界](safety-boundary.md)及 [AGENTS.md](../../AGENTS.md) 为准；状态不是执行授权或验证结论。

## 1. 身份与变体

- 原始材料用 intakeId/rawItemId；派生任务用 batchId+taskId 唯一定位，一个任务固定一个源→目标方向。caseId/路径是关联信息，不代替 taskId。
- 同一数据集的持续任务保持一个 batchId；新增材料分配新的 intakeId，追加原始去向和派生任务，已完成项不重编号。batch.json 保留集合版本/追加依据；已关闭批次追加前先记录重开与新范围，不把 ACTIVE 项静默放进 CLOSED。单项仍逐项冻结、立即推进，不批量冻结。
- 修改已冻结源码、方向、模型、知识正文快照、OS、工具链、输入/oracle 或比较条件时创建有父版本关联的变体/新 run，不覆盖原记录。新变体仍关联原批次；是否重新分类按[分类准入](../workflow/classifier-agent-gate.md)核对分类输入和条件，不能用新 run 重置既有问题的累计修复预算。只是补齐记录或恢复原冻结字节不改变这些条件，但须有原件对应依据。
- 源未变的目标代码 repair 在同一 run 内另存目标版本；环境恢复的原条件重提另记 attempt/job，不计新任务。首次/关联变体的 run 输出落点按[交付 §2.1.1](delivery-handoff-contract.md#211-单文件任务的标准骨架)，当前指针与旧原件分开；不借固定 batchId 目录覆盖历史。

## 2. 冻结记录

正式转换在分类前逐项冻结，并按 §2.2 写出、回读本 run 的 `01-frozen/frozen-inputs.md` 后才能推进。冻结不等于准入、可构建、评估就绪或已授权。记录字段按任务模式填写；不适用写明理由，未知事实写待准备，不伪填已核验。

| 组 | 内容 |
|---|---|
| 身份 | batchId/taskId/direction、caseId、casePath+caseSha256、源文件集合、sourcePath+sourceSha256 |
| 源/目标配置 | sourceOs/targetOs、候选 sourceOsBasis、架构/ABI、实际条件分支、语言标准、工具链/SDK、依赖及检查上下文 |
| 知识与模型 | selected skills（路径+哈希）、配置模型/温度、RAG 开关、不发送 max_tokens 的输出约定 |
| 构建与源基线 | 两侧 buildCommand/环境/工程输入；源预检适用运行条件与观察目标；真实构建诊断及适用运行/清理证据取得后追加引用，不倒填成冻结前已知 |
| 评估计划 | driver（形态、来源、argv/stdin、就绪条件、终止）、driverRationale、input/初始状态、oracle 是否适用及其来源/观察范围/比较策略 |
| 评估系统可达性 | 按评估准备 §1.0 记录本项检查时间、实际提交端/端点、原始健康响应或传输诊断指针、可达性结论及正常/仅转换分支；不可达时源/目标编译运行未开展，计划与实测分开 |
| 授权与环境 | 授权来源/范围/有效期、计划与已核验 runner/快照分开、实际网络/数据边界及清理条件；外部表单按适配页填写 |
| 恢复 | 原始/分类/冻结快照对应、父版本、有限修复预算、超时/轮询计划和待补项 |

输入没有独立 case.md/接收清单时，不为填 casePath/caseSha256 另造第二份冻结；记录实际输入来源、任务身份与精确源集合/字节依据，这类独立材料字段有理由地记不适用。已有 case.md 或清单按实际对象记录路径/摘要并保留，不能把目录/显示视图的摘要填成源文件字节摘要。冻结门禁的必备正文始终是本 run 的 frozen-inputs.md，其他接入说明不替代它。

片段的源侧预检只引用用户或获批平台已提供的精确中性声明上下文；缺源声明/依赖仍待准备，不由 Agent/模型新造桩、入口或依赖。正式转换须先过冻结、分类 ALLOWED 和适用源构建；正常行为分支还须有有效源运行基线。本轮无法合法行为评估但源构建通过时，按[评估准备 §1.3](evaluation-readiness-contract.md#13-lib_unobservable_compile_only-的转换与交付)在既有评估计划中记 LIB_UNOBSERVABLE_COMPILE_ONLY、具体行为缺口及目标语法/编译范围后继续生成；driver/input/oracle 的行为部分有理由地记不适用，不豁免目标验证。库可保留单文件模式，无需改源包名或补 main。纯文档审阅不触发动态步骤。

评估计划在冻结阶段确定；缺驱动、工具链或隔离证据不伪称行为就绪。系统可达但本轮无法合法评估行为时按 LIB_UNOBSERVABLE_COMPILE_ONLY 转换并验证目标语法/编译，缺入口不阻断已满足条件的生成；工具链/隔离缺口仍阻止受影响的验证动作。确认不可达则按评估准备 §1.0 记录仅转换、自审与交付，不要求本轮实时工具链或隔离证明，未知事实记未核验。已有 run 改范围按 §1 另记变体，保留历史，不以改范围抹掉真实行为失败。

评估计划的具体内容消费[评估准备 §4](evaluation-readiness-contract.md#4-oracle-与两侧对称)：源行为/消费者、输入与初态、观察对象/范围/单位、允许关系/保护项、实际模式及未覆盖部分放在本项既有记录，不新建 schema。环境变量的继承/未设置/空值、独立中性 cwd 和文件副作用按实际平台语义记录，空 JSON 对象不证明环境为空。候选条件只记录与本源行为有关的已考虑选项、依据和未决缺口，不要求穷举所有可能输入。

### 2.1 版本关联与复用边界

下列关系记录在既有冻结、模型元数据、provenance、decision 和 job 记录中；可用实际路径/已有身份表达，不另建第二套关联文件或平台字段，仍须保留 §2.2 要求的 frozen-inputs.md：

| 关系 | 必须能回读的对应内容 |
|---|---|
| 冻结 → 实际请求 | 本 run 的源范围/依赖、契约版本、所选本地知识正文及章节/快照、模型参数；分段注明实际注入范围。读取过文件或列过路径不等于已交给模型 |
| 请求 → 响应 → 目标 | 请求/attempt、实际返回模型、原响应、解码/取文件或机械补丁依据、父目标及新目标版本；HTTP 封装、解码正文和目标文件的哈希分别标明对象，不能互换 |
| 目标 → 自审/裁决 | 被审版本及范围、reviewN/attempt、原条目、追加裁决依据和仍未覆盖部分；不把旧稿审阅自动移到新稿 |
| 提交 → 证据 → 最终交付 | attempt/capsule、分类与授权引用、jobId、双侧实际输入/构建/运行/策略及原始证据、根级交付版本；“最新 job”不能代替版本对应 |

逐项回查时同时注明哈希/身份对应的对象层次：源原字节、LF 计数/显示视图、分类输入清单、脱敏请求正文、HTTP 响应封装、提取目标及 capsule 是不同对象；不同对象摘要不要求相等，同对象身份不明也不能用归一化相同代字节一致。分类当前指针须指向本项条件适用的原 classification-N，成功/失败旧件、拒收和更正依据一起留存，不从最后一个文件名推有效版本。

| 既有记录 | 职责与回查边界 |
|---|---|
| 接收清单/manifest | 材料接入、候选身份和实际文件集合；不能代替冻结门禁、实际模型请求或终态状态 |
| frozen-inputs.md、分类输入及运行 profile | 各自记本 run 冻结条件、当次分类集合与实际评估输入；对照身份/字节及字段含义，不强求清单 JSON 同哈希，不静默更新旧冻结 |
| model/provenance/review/decision/job 原件 | 保存实际发生的成功/失败请求、正文/提取依据、目标与被审版本、提交/回执/原观察；摘要/文件路径不能补出缺失正文 |
| batch items/events、单项 result 与检查点 | 表达当前去向/阶段/报告指针及发生/更正事件；同快照按唯一 taskId 对账。终态台账不能代单项原件，历史“未运行”栏不能覆盖真实已发生的 job |

恢复或结论更新先顺着上述链回读到当前精确交付版本，检查缺项、错项、重复及两向差集；只追加有原件支持的更正/缺口，不补造当时已消费知识、已通过分类或已执行。模板路径/输入默认值只有被本项事实替换并回读后才可作为材料；同源、同名模板或新稿更“完整”均不能替代版本证据。状态及模型/修复预算仍按既有规则，不因整理关联而新增 task/run 或重置计数。

关联缺失只说明不可复核，不能据此补造请求正文、目标来源或 PASS。原条件重提仅在源集合、构建/运行条件、输入/初始状态、oracle/策略、环境及授权仍适用且无未决执行时成立；源预检证据复用按[评估准备 §1.2](evaluation-readiness-contract.md#12-源基线复用与失效)核对。冻结知识后来被修改时，已有 run 继续指向原快照；拿不到原正文就记缺口，不能以仓库当前页回填历史注入。

冻结说明的事实/表述有误时，对照精确源码、原请求和实际条件追加更正及其依据。仅注释更正不伪装成改变过输入或重新执行；如果更正会改变实际契约、允许差异或准备条件，则另记变体并重新核受影响门槛，原说明及原结果保留。

已确认转换缺陷的状态与评估阻塞原因分别保留，沿父目标→修订→复审→独立验证对应；ORACLE_NOT_FREEZABLE、LIB 范围、residualRisk 或本次 matched 不自动使其解决。修复改动的源语义依据与新稿验证缺口按单项闭环记录，停止时在 result.md 明示“未修复／已修订未验证／已验证解决”的实际情况；这些是报告说明，不新增平台状态或重置预算。

### 2.2 冻结落盘门禁

**`frozen-inputs.md` 是冻结完成的必备记录，必须先写出再回读，不能等收尾补件。** 落点按[交付契约 §2.1.1](delivery-handoff-contract.md#211-单文件任务的标准骨架)，属于本项约定 run 的 `01-frozen/`；明确文本交付、片段和仅编译转换同样适用。分类结果、case.md、batch/item/event、聊天中的计划均不能替代它；纯文档审阅和冻结前即排除/重复/跳过的项不要求伪建此文件。

1. **分类前核对**：人工读取实际文件，确认存在、可读且有实质内容；身份、方向、任务模式、run 落点及精确源集合/哈希与本项对应，§2 各组适用字段已记录。不适用有理由，待准备明确缺口；空文件、模板占位、另一项或旧 run 的记录不能放行。构建/运行诊断等尚未取得的事实只记计划或待取证，不要求提前填结果。
2. **后续与恢复核对**：进入源预检、每次正式模型请求（含自审/修订）、提交/重提以及恢复新增转换动作前，再回读此文件并核对当前动作的版本/条件。相关正文未变且有精确版本依据时可引用已有内容核对，不重复抄表；仍确认文件可读、记录适用。该动作所需的待准备条件未解除，不能仅因文件存在放行。查询未知提交、取回已发生证据及终止/清理不受缺件阻断，仍按原 job 身份和安全边界处理。
3. **保存检查依据**：在既有阶段记录中记真实路径/版本、核对时间、通过/缺口及下一动作；加载证据可由[登记工具](../../tools/README-loading.md)保存并引用，不新增通用状态台账或 Controller 字段。未完成本检查不得新记 FROZEN 或推进后续阶段；已有阶段和实际证据不因缺件被擦除或降成“未发生”。

人工回读时还核模板占位符是否已替换为本项事实、实际argv/stdin/cwd/env/超时/源集合是否对应计划，以及所引用知识是否只列标题而缺适用正文。用于接收的manifest、LF计数视图、分类输入快照、运行输入profile与终态items各有职责，不要求不同对象的文件哈希相同；也不把manifest的历史“未运行”栏覆盖真实已发生记录。字节身份、行数/显示计数、语义输入和任务身份分别对应，差异有依据地追加说明。

缺失、不可读或错位时先停止新增分类/预检/模型请求/提交，手工补齐并回读后才可继续；结束或暂停仍走[统一收尾入口](delivery-handoff-contract.md#11-统一收尾入口与报告义务)，保留实际阶段、准备缺口及恢复条件。历史漏写只能依据当时可回读的契约、请求和原始记录补录，注明补录时间、来源及仍未知部分；不能按当前目标/结果反推原冻结条件，不能把补录写成当时已通过前置检查。缺应有件仍不满足终态门禁。

本门禁由 Agent 逐项执行；加载部分回读系统登记工具提供的结果，无系统支持时以原生工具手工核结构版本、正文范围及既有消费时点，注明依据与限制；其余字段仍按本节回读。加载工具与分类器、Controller 校验分别承担职责，不自动修改状态。前置核对保障推进条件，收尾核对保障适用交付齐备，二者均须执行。

### 2.3 知识加载与实际消费

加载记录使用既有冻结、source-analysis（适用时）和请求元数据，不另建状态台账。系统侧可在冻结准备草稿或既有阶段记录内消费 `loading-preflight` 块，字段及命令见[工具说明](../../tools/README-loading.md)；结构报告和正文返回原件用不可变指针引用。第三方智能体不得调用辅助脚本，只通过原生工具回读系统原件；无系统支持时保存同范围 manual 核对，不伪造独立返回证据。开始画像前核 start，多项首项前含 batch，建图前核 map，冻结前核 freeze，后续正式动作前核对应加载条件。缺能力/返回依据记 UNAVAILABLE，不能把自填声明提升为独立返回证据。

正文提供证据只证明指定会话曾获得相应范围。跨会话、已知压缩/恢复或正文变更须重新核版本和提供范围；事后补读不追认历史动作合规。旧快照继续使用及变体按 §2.1，不用当前工作树更新旧凭证。查询/取证/终止/清理沿 §2.2 例外继续。

| 状态说明 | 所需依据 | 不能代替 |
|---|---|---|
| 可达 | 路径/锚点指向随仓库交付的实际正文 | 链接存在不证明 Agent 读过 |
| Agent 已读 | 读取范围完整，记录路径/章节、精确版本/哈希、源符号/范围与适用理由；每项必读源/目标两语言页和一个方向，其他页按触发 | 截断读取、标题或目录不能充作正文；尚未读取范围须补读或写缺口 |
| 模型已注入 | 实际发送的脱敏请求中含本轮适用正文/行为义务，并可回读到冻结快照与实际源范围；未发送只记材料已准备 | 本地已读、计划注入或仅列路径不证明模型收到；不把全部 Agent 调度文档无差别塞给模型代替语义选择 |
| 效果已验证 | 对精确目标版本有独立编译/行为证据，并确认相关规则实际触发及被观察范围 | 自审、规则标题出现或正文已注入都不证明应用正确/有效 |

读取语言页与方向页是必读义务；“按需”指规则适用性、场景/系统及专题触发和注入范围，不能用来省掉两语言页。正式生成、自审/修订请求前核本轮实际正文与冻结选择对应；缺必要语义、版本或源码对应先补材料或停止受影响请求，容量不足按长文件流程保持单元及依赖闭合，不静默截断。分类器消费源码分类输入，不需要把转换知识正文塞入分类清单。

**规则适用性先核再注入**：对本轮影响转换的条目，在既有冻结/画像/请求记录中对应源使用点、前提和适用范围。语言事实用于理解源，方向/场景/系统页的“可选”“近似”是有条件候选，不是必须替换的命令；没有源码触发的条目不注入为本轮义务。目标惯用写法、字段命名习惯、性能偏好不授权改变冻结接口、返回形态、序列化文本、错误、求值/异步时序或资源行为。规则与精确源事实/契约冲突时标出条目与影响，不能凭 Skill 标题覆盖源；必要语义未决则停止受影响请求，其余有依据的任务可继续。LIB_UNOBSERVABLE_COMPILE_ONLY 只改变验证范围，不允许删源行为或用错误语义求编译通过。

### 2.4 有依据的阶段推进

各步消费根调度表及对应真源，不另建第二套裁决。加载工具只核本节既有动作的加载前置条件。动作前在既有阶段/attempt/模型/job 记录中核当前身份、精确版本、前置条件及原件指针；动作后保存真实结果与失败原文，再记已达 phase 和下一动作。没有完成原件不把“准备/开始/已请求”记成“通过/完成”，口头声明或模型自评不替代证据。

- 分类放行据当前源集合对应的原 ALLOWED/null；源可构建据实际冻结命令消费的源版本及 build completed/0，不拿另一个包/文件或系统内置库的构建代替。
- 生成/自审据实际请求、完整响应、目标版本和追加裁决；提交前先保存精确 attempt/capsule/版本与恢复标识，HTTP 状态、body、传输退出/错误与 jobId 分别记实际事实。
- 正常行为分支核有效源基线、驱动/输入/观察/清理；LIB 分支按评估准备 §1.3 核原因、源构建及不运行的目标验证，不要求不存在的 execution/comparison。
- 评估系统不可达的仅转换分支按[评估准备 §1.0](evaluation-readiness-contract.md#10-转换前可达性检查与仅转换分支)核检查原件、冻结与 ALLOWED，允许 CLASSIFIED→GENERATED→SELF_REVIEWED/适用修订→部分交付；不记 SOURCE_BUILDABLE/EVALUATED，不要求未发生源预检原件。自审、目标版本/来源和 result.md 仍须完整。
- 恢复先处理未知提交/未决执行及清理，不能借新 run 开新执行或跳过原件；查询、取证、终止/清理继续按原身份。每次停止/暂停都走交付 §1.1；只有适用件核对齐备且没有未决执行才记 DONE/PARTIAL/CLOSED。

## 3. 接入去向

每个 rawItemId 的每个候选方向必须有一个当前去向，变化以追加记录保留历史。以下是封闭词表：

| 去向 | 含义 |
|---|---|
| FROZEN | 转换边界已在本 run 的 frozen-inputs.md 落盘且回读通过（§2.2）；仍须逐项分类，系统可达时再过适用源侧预检才能生成；不可达分支按评估准备 §1.0 |
| PREPARATION_GAP | 方向/平台/模式、快照或所需合法准备件不足，待补 |
| DUPLICATE | 同源同向同契约且非显式独立试验；指向复用任务 |
| EXCLUDED | 不在任务范围，记依据 |
| SOURCE_NOT_BUILDABLE | 源侧预检真实诊断确认源平台/接口不可构建，非转换失败 |
| SOURCE_DEPENDENCY_GAP | 源引用快照外真实依赖；快照内文件漏打包不属此项 |
| SAFETY_BLOCKED | 安全文本处理/交付也不允许；不外发凭证 |
| SKIPPED | 本机无法读取/校验源字节且未取得可复核快照；能读能校验的项不能用此去向 |

已冻结项的分类阻断保存原 admissionStatus/blockingReason，并用 lifecycle/pendingAction 记录等待或停止，不新增第二准入裁决。LIB_UNOBSERVABLE_COMPILE_ONLY 是本轮语法/编译验证范围及行为未评估原因，不是不可转换去向；记录实际 phase，只有真实生成后才记已转换，不因缺 main/可执行文件/stdout/合法评估入口直接记 PREPARATION_GAP 并跳过生成。

## 4. 阶段、生命周期与验证结论

| 字段 | 语义 |
|---|---|
| phase | 最近有完整记录的单项闭环阶段；分类及本轮适用的源侧预检是生成前条件，不把动作开始写成完成；不可达仅转换不虚记源预检阶段 |
| pendingAction | 当前进行或等待的动作，关联请求/attempt/job 身份 |
| lifecycle | NOT_STARTED / ACTIVE / WAITING / DONE / PARTIAL |
| 原因与恢复条件 | 分类阻断、准备缺口、SELF_REVIEW_UNRESOLVED、RUN_SAFETY_NOT_READY、BLOCKED_ENV（有真实环境诊断）、SUBMISSION_UNKNOWN、LIB_UNOBSERVABLE_COMPILE_ONLY、EVALUATOR_UNREACHABLE_CONVERSION_ONLY（本项目范围/原因，非平台字段）、ORACLE_NOT_FREEZABLE 等；保留解除历史 |
| 验证结论 | 按精确版本分列 source/target build、execution、comparison、环境与安全；原平台 verdict 与本项目覆盖判断分列 |

DONE 表示契约所要求的工作、取证和交付已收尾，**可有真实失败**；PARTIAL 表示本轮已停止并完成适用的部分交付，仍缺工作/证据。两者都须先过[交付完整性门禁](delivery-handoff-contract.md#211-单文件任务的标准骨架)，对应闭环 CLOSED。matched/mismatched 不决定 lifecycle，缺证据为 UNVERIFIED。

每个已处理项结束/暂停时按[统一收尾入口](delivery-handoff-contract.md#11-统一收尾入口与报告义务)保留 result.md 及实际产物核对，成功、失败、生成前阻断和非可转换去向均不豁免。WAITING 报告说明暂停与恢复条件，不表示 CLOSED；缺报告/核对记录不能记终态，报告存在也不能解除未决执行。

平台报告“终态”与本项 lifecycle 分开：使用 Controller 时按[当前协议适配](../adapter/controller/platform-revision-adapter.md)核平台身份、closure/原件与真实清理；仍收尾阻断或接收/调用/清理未知保持 WAITING。submissionId 只绑定精确提交尝试的恢复，不代 taskId/runId、不增加任务数，也不允许改冻结条件沿用旧 ID 重执行。

仅编译项固定 PARTIAL、功能 UNVERIFIED，编译据实。源不可构建/依赖缺口不回填目标 FAIL；非可转换去向按适用件收尾，不纳入转换失败。可能已接收但缺回执，或 job 仍活动/未确认清理时保持 WAITING，不能用 PARTIAL 绕过未决执行。恢复 PARTIAL 追加重入依据，从最近适用阶段继续且保留预算。

EVALUATOR_UNREACHABLE_CONVERSION_ONLY 属已转换后的部分验证交付范围，不新增接入去向或 Controller schema。完成转换、自审及适用件核对后 PARTIAL，源/目标编译、运行与功能比较未开展为 UNVERIFIED，不记源不可构建或功能失败。恢复可达先补适用源预检再验证已有目标，按评估准备 §1.0/§1.2 核旧证据及关联变体，不重复成功生成或重置预算；已有未决执行优先保持 WAITING。
