# 评估准备与观察有效性契约

本页维护 Agent 的提交准备条件与证据采信边界；不产生第三方功能 PASS/FAIL，不建设驱动、比较器或运行时。单项闭环规定何时核对，[行为指导](../workflow/behavior-preservation-contract.md)整理目标与允许差异，[Controller 适配](../adapter/controller/remote-controller-adapter.md)规定外部字段。执行红线以[安全边界](safety-boundary.md)及 [AGENTS.md](../../AGENTS.md) 为准。

源预检及每次提交/重提前，先按[任务状态 §2.2](task-state-contract.md#22-冻结落盘门禁)回读本项本 run 的 `01-frozen/frozen-inputs.md`，核路径/版本、适用内容及当前动作所需条件；缺失、空白或错位不进入新 job。已有 ALLOWED/预检 PASS 不替代本检查，未知提交的查询、取回已发生证据及终止/清理仍按原 job 处理。

## 1. 适用分支与提交条件

采用 Controller 渠道时，源预检/双侧仅编译的具体接口、报告 kind 与平台身份核对消费[当前协议适配](../adapter/controller/platform-revision-adapter.md)，本页门禁不因平台回归通过而解除。源侧报告的有限 oracle PASS、平台收尾完整性与有效业务基线分别核对；版本不符或支持未知记准备缺口，不造 target 补预检。

| 分支 | 提交前必须核对 | 功能结论 |
|---|---|---|
| 源侧预检（首个通常记 job-00，后续按实际编号） | 已冻结且分类 ALLOWED、安全/独立授权/逐例隔离、精确源集合、真实工具链和源 buildCommand；需行为评估时还核源侧合法驱动四要素、冻结输入/初始状态与观察目标，并实际运行源取得有效基线（见 §1.1/§1.4）；此时不要求目标生成/自审 | 分列源 build 与适用 execution/原始观察；源基线有效不证明目标功能一致 |
| 正常双侧行为评估 | 分类/源侧预检已通过、内部自审记录完整、安全与独立授权/隔离、驱动四要素、两侧对称、适用 oracle 和平台支持 | 只据精确版本真实观察与比较，限定覆盖 |
| LIB_UNOBSERVABLE_COMPILE_ONLY | 本轮无法合法评估行为的逐项原因（缺合法入口/观察条件/平台维度或确无安全观察方式）、冻结、分类 ALLOWED、源构建 completed/0、内部自审及安全边界；用平台支持的不运行命令验证精确目标语法/编译，不补造入口、不要求链接可执行 | 行为未评估/UNVERIFIED，PARTIAL；源构建与目标验证分列，不采信空输出 matched |
| 明确文本交付 / 无行为评估的片段 | 不提交行为评估 job；按任务契约交付文本及已取得的适用预检证据 | 未开展维度 UNVERIFIED，不要求伪造 driver/oracle/job-01 |

分类 ALLOWED 不替代执行授权；READY/clean/快照不证明隔离。提交前按[分类准入](../workflow/classifier-agent-gate.md)核源文件集合、分类身份/哈希及授权，按[构建前提](../workflow/build-prerequisites.md)核实际工具链。任一适用条件不足先补准备，不能消耗一次评估来掩盖已知装置缺陷。源侧预检使用现役平台已支持、获授权的形态；接口或准备件未知时等待，不提前生成转换目标来凑预检 capsule。仅编译分支仍须核实平台确实不运行样本。

### 1.1 生成前源侧预检

源侧预检先确认源可构建；正常行为分支在生成前再取冻结条件下有效、可复核的源运行基线。LIB_UNOBSERVABLE_COMPILE_ONLY 按 §1.3 不强迫源运行，源构建通过后继续生成并验证目标语法/编译。所有构建/运行均在获批隔离 VM 内进行；源运行仍受分类、合法驱动、安全与独立授权约束。

- **构建门槛**：源 `build.status=completed` 且 `exitCode=0`。是否可构建只由真实编译器诊断定案；失败按构建前提分流，不把运行问题记为 SOURCE_NOT_BUILDABLE。
- **运行与观察门槛（需行为评估时）**：按冻结 argv/stdin 与初始状态启动源、到达被观察状态、采集真实 stdout/stderr/退出码及约定副作用、终止并核实清理；以 §4–5 的观察有效性要求核对源结果与冻结观察目标。服务不要求自行退出，预期错误路径也不要求退出码为 0。“正常”指满足该项冻结条件；仅有 build 成功、退出码 0 或非空 banner 不能代替约定行为的有效基线，也不证明未覆盖分支正常。
- **基线缺口**：计划行为评估但源未到达观察状态、装置失败、输入未送达、证据不足或观察条件无法冻结时，先停止该行为评估并分别归因；不得冒充有效基线。没有有效源基线时，正常行为分支不生成；但源构建已通过且满足 §1.3 的项可显式改走本轮语法/编译交付，继续生成，不按观察缺口直接判不可转换。源运行失败不自动证明源不可构建，更不是目标转换失败；实际失败原件不得因改分支删除。
- **不适用运行的分支**：明确文本交付/无行为评估的片段，以及按 §1.3 逐项记录原因的 LIB_UNOBSERVABLE_COMPILE_ONLY，源侧按声明上下文仅做适用构建预检，不强迫运行完整程序；记录原因，功能 UNVERIFIED。可安全观察但本轮缺合法入口也可采用该分支，不必证明永远无法安全观察。

片段需要的中性声明上下文只引用用户或获批平台已提供的精确版本，记录来源、版本和范围；若进入源树则纳入冻结集合与分类输入。声明上下文不提供新业务行为、驱动或虚假依赖，Agent/模型不新造桩或入口来补件；缺合法上下文待准备，不以伪造声明取得构建 PASS。声明性工程配置的有限补齐只按[构建前提 §3](../workflow/build-prerequisites.md#3-c-csproj-补齐的三个硬性要求)，不等同于程序桩。

预检 job 的源 build、适用 execution、原始观察、版本/输入身份和终止/清理证据一起保存到既有 `job-00-source-buildability/returned-evidence/`；目录名沿用，不表示只允许构建。源预检不需要目标自审或双侧 comparison，也不产生目标功能 PASS。后续双侧评估仍须核对两侧精确版本与有效观察，不能只用旧源运行摘要代替。

### 1.2 源基线复用与失效

已有精确源预检记录不因单纯目标 repair 而重复执行，但先核源集合（含驱动/fixture/工程输入）、构建条件、工具链/平台、适用 argv/stdin/初始状态、观察目标及实际环境前提均对应。只复用未变条件支持的结论：源构建未变不能证明新输入的运行路径已观察；旧源观察也不替代新目标版本的独立证据。授权仍有效、逐例隔离与当前环境清理另核，不能由历史记录继承。

源或源侧条件改变时，保留旧记录，按任务状态契约另记变体及分类触发项，重取受影响源构建/运行基线后才能生成。依赖/入口原件、精确版本或适用性不明时停止受影响阶段，不用同文件名、同摘要、已有一次 matched 或当前源码“看起来一样”代替。实际后续预检按发生顺序另记 job，不覆盖 job-00。

### 1.3 LIB_UNOBSERVABLE_COMPILE_ONLY 的转换与交付

**能合法评估行为的继续评估；本轮无法合法评估行为、但源可构建的，记 LIB_UNOBSERVABLE_COMPILE_ONLY，继续转换并验证目标语法/编译。** 该既有名称表示本轮评估范围，不是不可转换去向，也不要求证明永远无安全入口；本轮缺合法入口与结构性无安全观察方式分别记录原因。这是当前用户明确允许的分支，不逐项重复确认，不豁免冻结、分类、源构建、知识/模型来源、自审及安全边界。

1. **先核行为路径**：有没有 main、可执行文件或 stdout 不是判据；库函数返回值、参数修改、错误和副作用也可观察。已有适用的合法入口/向量、观察条件与平台支持时走正常行为分支，不为省事省略；缺合法入口、无法冻结有效观察或平台不能采集所需维度时，记录具体缺口后可采用本分支。
2. **生成放行**：精确源集合已真实构建 completed/0，适用清理已确认，分类 ALLOWED，源接口/必要上下文与目标表示足够明确，不存在阻止文本转换的安全或授权问题；冻结记“本轮仅验证语法/编译，行为未评估”及原因，即可生成、自审。不得将缺评估入口写成 SOURCE_DEPENDENCY_GAP 或不可转换。源构建失败、源声明/依赖缺失、影响实现的契约未知等仍先停，不让模型补造源条件。
3. **保持源形态**：库/完整文件可沿用单文件模式，以片段式语法/编译范围验收，不强制把 taskMode 改为片段。保留函数/模块接口及源行为义务；不改源包名、不新增 main、桩、业务入口或辅助驱动，不委托配置模型造评测程序。真正片段需要的中性声明上下文仍只能引用合法提供版本。
4. **目标验证**：自审后在获批隔离环境，用精确目标版本对应的编译器/解析器及已支持的不运行形态取真实语法/编译证据。无需链接可执行程序或运行目标。PowerShell 等解释型目标核实际语法解析，不把脚本执行当语法检查；语法/构建、加载及启动行为按[构建前提 §2.4.1](../workflow/build-prerequisites.md#241-检查阶段与结论范围)逐层判读，不以 shell 0 代解析错误检查。自审和源 build PASS 都不能代替目标证据。目标验证条件暂缺不反向阻止已有条件的生成，先交完整目标并写目标 UNVERIFIED 与待补验证；不造 build job 或 PASS。
5. **版本与报告**：已有 run 改评估范围，按任务状态 §1/§2.1 另记关联变体，保留原冻结与失败记录；未变源构建仅按 §1.2 复用，不重置修复预算。本轮写“已转换；目标语法/编译据实；行为未评估/UNVERIFIED”及缺口，适用件齐备后 PARTIAL，不当非可转换去向。未知提交、活动或清理未确认仍 WAITING。后续合法行为条件补齐时另冻评估条件，继续验证，不把本轮结果改写成功能 PASS。

实际运行故障或行为差异须先归因，不能直接说成“没有入口”或抹成 not-requested；若无法取得有效行为评估而转本分支，保留真实失败与未确认行为，不能借仅编译修复源问题或宣布等价。已有合法路径且实际完成行为评估但发现差异的项，按真实结果与有限修复处理，不为躲避 FAIL 改为未评估。

### 1.4 源预检采信与双侧对齐核对

生成前人工回读源预检原件；正常行为分支提交前再把目标条件与有效源基线逐项对齐。以下清单落实 §1.1–1.3、§2/§4–5 的已有义务，在本项既有记录/result.md 中保存原件路径、精确版本、核对结果及缺口，不新增平台字段、检测器或辅助驱动。条件未变且证据适用时按 §1.2 引用，不为填写清单重复运行。

| 核对对象 | 要读到的事实与不满足时的处理 |
|---|---|
| 预检身份与范围 | 本 run 的源集合、冻结版本、实际 job 编号/用途及报告 kind/version 对应。Controller 的 source-only 形状按当前协议适配 §2–3；只含源预检，不造占位 target。历史双侧 job 若带占位目标，保留原报告，目标/comparison 不纳入转换功能统计；源部分也须独立核实身份、构建和适用观察，不能因旧 matched 就采信基线 |
| 真实源构建 | 原 build 阶段、实际整数退出码、诊断及工具链/构建条件对应；completed/0 才满足源构建门槛。执行 completed、job 终态、report 总标签或驱动启动失败都不能代构建诊断 |
| 冻结输入实际送达 | 回读真实请求中的 argv/stdin、入口和合法驱动精确版本，再核原始观察是否支持所声明路径；请求写了参数只证明计划/发送形状，不证明驱动转发。驱动吞参数、输入文件未送达或只有 usage 时，不能据两侧相同推断业务覆盖。argv=[]、stdin=null 可以是合法冻结输入，不强制非空，也不要求程序新增参数回显 |
| 两侧初始条件 | 核各侧实际启动入口、工作目录/环境前提、fixture 内容与状态、观察范围、超时/终止安排是否满足同一冻结条件。脚本与二进制入口可不同；对齐的是可观察语义与初始资源，不要求跨系统路径字面相同。构建产物不得混入业务枚举/文件观察；命令模板、同名 fixture 或清单宣称相同不足以代实际依据 |
| 到达状态及程序观察 | 读程序流、实际退出/超时和适用副作用，区分驱动日志、包装协议、构建日志及程序输出；按已知包装协议取内层观察，外层 JSON 相等不证明业务 JSON 相等。非空 banner 不证明到达业务状态；无 stdout/stderr 但有效退出/副作用足以区分未工作并满足 oracle 时仍可有效。冻结预期错误路径可含非零退出，不能强求成功路径；空输出或相同装置错误本身不构成有效基线 |
| 观察能力与覆盖 | 核维度是否实际采集、截断/摘要是否足以支持该义务及独立 oracle 的适用范围。未知来源、缺原件、只剩长度或未支持维度记具体缺口/UNVERIFIED；有限 oracle PASS、closure complete 或 provenance 未验证不补足来源/业务覆盖，不扩大到未观察分支 |
| 终止、清理及后续版本 | 核本次源预检及适用侧的真实终止/清理；有活动、未知提交或清理未确认按状态契约保持 WAITING。源基线只用于对应条件，目标修订必须取得新目标独立证据；不继承占位目标或旧目标结论 |

核对后分别决定源可构建性、基线适用性与当前分支：真实源构建失败按构建前提处理，不调用转换；源构建已过但本轮缺合法有效行为条件，保留已有失败/缺口并按 §1.3 显式记录仅编译范围后继续生成；合法条件齐备的仍走行为分支，不为躲避真实差异转未评估。证据有效后才进入 §5.1 的消噪、功能分类及统计，原平台标签始终保留。

## 2. 驱动来源与四要素

driver 是真正启动、观察和终止程序的契约角色，不强制 Python。source/run_case.py 与 target/run_case.py 等须来自用户或获批平台已提供的精确版本，保留来源/哈希；Agent 不编写、生成、保存新的辅助驱动/工具，不委托配置模型绕过。手工组装只引用/归位合法输入。缺来源或需要改驱动时，行为评估待准备并说明提供者；源构建已过且满足 §1.3 可先完成转换与目标语法/编译交付，不因驱动缺件直接跳过该项。已生成项保持其已转换身份，不能改接入去向来免 target/result 等应有交付。

源侧驱动位于 source/ 树时须一同分类；目标侧驱动不由源分类覆盖，仍须独立文本审阅。驱动与中性入口不能新增源业务行为、真实依赖、外联或权限能力。

| 要素 | 合格 | 不合格 |
|---|---|---|
| 启动 | 按冻结 argv/stdin 启动实际构建产物 | 默认参数、吞 argv、省略输入 |
| 到达被观察状态 | 确认契约声明的状态，服务等到相应就绪条件 | 启动即判；用旁证替代 oracle 要求的观察量 |
| 采集 | 实际 stdout/stderr/退出码及声明副作用 | 固定值、长度摘要、空跑 |
| 终止 | 观察完成后终止并清理，不留进程 | 无限等待、依赖外部超时兜底、残余进程 |

命令行退出型可直接运行并捕获；服务按冻结入口启动→等就绪→固定请求→采集→终止；交互按冻结输入；一次性副作用要观察其结果。不能把为一个服务设定的 argv/协议原样套到另一个。

合法驱动须覆盖本侧真实产物形态：编译型构建产物与解释型脚本分别按冻结入口启动，不能固定只找 program.exe/program。采集按约定保留程序 stdout/stderr 字节、实际退出和副作用，驱动自身日志/失败标记另辨来源；将流包装为 JSON、文本再编码、追加回显不能冒充原始流。需要这种形态的现成驱动不存在时待合法提供者补件，不由 Agent 实现。

服务 banner 等流观察须在进程存活期持续采集；不能只在 terminate 后读取而丢缓冲。持续读取不证明程序内部缓冲已刷新，须核实际取得的观察。就绪判据必须覆盖契约所需观察量，端口可连不自动证明日志已采得或业务请求已完成。同一路径连续两次装置失败停止本轮，记 UNVERIFIED/覆盖缺口，不重复求绿；后续由合法来源修正装置后另记版本重取。

## 3. 无安全可观察入口

判据是能否用中性/公开输入、不编造源行为、不触发 UB、不连真实目标、不无限阻塞地观察源声明行为，不是有没有 main。

LIB_UNOBSERVABLE_COMPILE_ONLY 按 §1.3 表示**本轮无法合法完成行为评估、改做语法/编译交付**；本节标题与旧锚点保留。判断实际可观察性和当前入口是否齐备，不能把“缺 main”当无法评估的充分证据，也不能要求入口缺件的项永远等待而不转换。

- 能安全观察：合法入口/向量等条件齐备时走四要素+oracle。确定性库及公开测试向量属于此分支；本轮缺合法入口时可记 LIB_UNOBSERVABLE_COMPILE_ONLY，按 §1.3 继续转换并验证目标语法/编译，注明“缺合法入口”而不是“永远无安全观察方式”，不自行造驱动。
- 确属不能安全观察：逐项举证后记 LIB_UNOBSERVABLE_COMPILE_ONLY，仍按门禁转换并移交双侧仅编译。编译据实、功能 UNVERIFIED、PARTIAL；比较器的空输出 matched 不采信。

固化形态：公开向量可观察且合法入口齐备的 Rc4Initialize/Rc4Process 库走完整验证，入口缺件按 §1.3；需要编造合法 PE 输入且短缓冲触发 UB 的装载库、或无法有界观察的退化/headless 入口可记结构性仅编译。具体是否成立仍须按该源举证，不能按文件名套用。

Controller 是否支持只编译不运行须按现役接口核对，未知时待准备；不能为获取 build 偷偷执行禁止的入口，缺证据据实记 UNVERIFIED。INCONCLUSIVE 是可修复的观察装置缺陷，与结构性无安全入口分开。

## 4. oracle 与两侧对称

oracle 是条件义务：需功能评估时冻结输入、初始状态、观察维度、比较策略与独立来源；无需行为评估时写理由。评估就绪门禁检查的是该状态及其适用性，不要求每项造一个 oracle。不以目标稿/目标答案反向定义正确。

冻结前核可复现性：观察量会变且未被实际平台消噪/已确认策略覆盖时，记 ORACLE_NOT_FREEZABLE + UNVERIFIED，停止该行为评估并部分交付；需要结论时另冻条件，不重复重提掷骰子。平台字段与配置支持以适配页及实时证据为准，不把服务器三类消噪 token 当作通用语义 oracle。

提交前另核两侧对称：argv/stdin 原样送达；argv 点名文件两侧存在且内容一致；初始目录和构建产物不能污染契约要观察的条目数；回显、追加标记、归一化等后处理一致。必要中性 fixture 必须有合法来源和冻结说明，不补造业务结果。脚本与二进制不同启动路径不能导致只对一侧后处理。

观察维度须对应冻结行为义务：文件输出要取得实际文件内容/约定元数据证据，数量、总长度或 stdout 回显不代替文件维度；采集与比较范围均显式列业务副作用路径，不用全工作目录模式纳入构建产物。某个清单字段动态，不自动放弃其他确定文件的观察。具体能力和字段见[比较策略适配 §3](../adapter/controller/comparison-policy-adapter.md#3-文件消噪观察范围与保护范围都要声明)；未支持或未采集的义务如实留缺口，不缩减范围来求 matched。

## 5. 原始观察、采信与归因

轮询到 job 终态后取 report、双侧原始 evidence、comparison、logs；中途快照仅作进度。先核精确版本/输入/工具链，再核输入实际送达、两侧到达被观察状态、源观察非退化且对应同一 oracle。非空 stdout/stderr 只是观察候选：仍须区分程序输出与驱动失败，并确认内容属于冻结路径。两侧相同 usage 仅在契约明确观察该用法错误路径且输入实际送达时才有意义，不能证明被吞 argv 后未进入的业务路径。无 stdout/stderr 但真实退出/副作用足以区分未工作且符合 oracle 的项也可有有效观察；两侧空输出/同一驱动失败标记不能单独支持 matched。

原平台 behaviorVerdict 原样保留，与本项目覆盖结论分列。matched 不是编译证据；semantic_pass 的允许差异逐条列依据和归因，维度计数不能替代档位；缺对应维度/基线/原始观察为 UNVERIFIED。仅编译永不写功能 PASS，不合成单一成功率。

### 5.1 有效性、消噪与功能分类的次序

先核精确版本、输入送达、真实程序/装置来源与适用观察，再按冻结允许差异进行消噪，最后读取平台功能分类并做分层统计。消噪可以宽泛到跨语言/系统的展示差异，但不是用来解除观察缺口或删除行为义务。选择可复用的语义关系优先于反复要求表面字节相同：路径对应、重复动态值关系、无顺序义务集合、对象键序、允许的错误展示形式均可提出；平台未支持的需求写具体能力缺口，不由Agent实现比较器。

| 差异类别 | 可接受范围与受保护的行为 |
|---|---|
| 路径/动态标识/展示时间 | 允许已确认的对应位置或值不同；保留相同资源重复引用和实际指向，关键相对路径、固定端口、有效期及采样窗口不自动忽略 |
| 结构/表示 | 对象键序和展示格式可按业务语义比较；保护字段集、类型、值、缺失/null、顺序有义务的数组、业务字节和数值精度 |
| 运行时诊断 | 错误外形可有允许差异；仍核失败类型、发生时机、退出/续行、源捕获范围和业务副作用，不能一律忽略stderr |
| 装置/构建背景产物 | 构建日志不当程序输出；构建制品与业务文件按冻结对象/范围区分，不以忽略所有exe/临时文件掩盖真实新增副作用 |

冻结宽泛消噪时，在既有比较计划逐项写“差异来源/对象→允许关系→保护项→平台实际模式与覆盖”；优先采用业务允许的结构/关系比较，不按语言名或样例字段名整类删除。以下是选择引导，不是新增平台能力：

| 可讨论的关系 | 保护项及实际支持不足时的处理 |
|---|---|
| 跨系统工作根、临时位置、资源标识的对应 | 同一资源重复引用、相对名称/内容/用途和关键端点仍要核；路径 token 只证明文字归一，不证明实际访问对象相同 |
| 无顺序义务集合或 JSON 对象键序 | 先核源消费者是否观察顺序；成员、重复次数、类型/值、缺失/null 和有序数组受保护。仅现役 json-structural 能支持的范围才用；不把整流排序或删行当通用消噪 |
| 错误堆栈/运行时展示差异 | 核同一冻结错误路径、发生时机、捕获/续行、退出和副作用；panic/traceback 名称或长短不同不直接要求模型修展示，也不自动允许错误类别/退出变化。平台缺错误关系映射时记具体缺口，保留原判 |
| 归档的压缩表示、archive_bytes 等派生展示 | 若业务按合法归档/成员/CRC/解压内容验收，可提出允许压缩大小/表示差异；若冻结字节、签名或协议长度为义务则保护。必须有实际内容观察及支持策略，不能单凭字段名删除数值 |
| host:port 或动态时间值 | 核冻结要求的地址/固定或动态端口、同一服务关系、时间定义/窗口；端口形态或高位范围不证明动态可替换，不吞连接错误、有效期或采样定义 |

允许关系只有在冻结义务支持、合法观察齐备且平台实际实现适用时才采信；服务器 preset 名或全流 token 不能证明每个关键字段都被保护。没有细粒度支持的混合流保持已冻结严格义务或移交具体能力需求，不新造 InputProfile 字段、装置预处理或 Agent 比较器。构建/驱动日志先按来源区分；分不清时记证据缺口，不能把“看起来像噪声”的整段删掉。记录仍保留原始输出、实际规则命中和未覆盖范围。

有效matched与有效semantic_pass均可进入“本冻结观察范围内功能比较通过”小计，分别保留两类数量、策略/规则、观察范围和未覆盖义务。是否需要独立功能oracle仍按§4及平台实际协议；平台标签不是普遍等价或完整业务通过。无效观察、装置失败、无关键维度、仅编译和缺对应证据的项单列，不靠标签进入该小计；小计不代交付、编译或安全结论，也不合成全批转换成功率。

JSON结构策略消费的是实际结构值；若JSON只是驱动外包装而stdout内仍是字符串，不据外层匹配声称内层业务JSON已结构比较。collectorDiagnostics空只表示未记录诊断，output.events空不表示stdout/stderr为空；completed表示阶段结束而非exitCode为0，closure完整也不代表业务义务通过。原始采集的截断、展示工具截断与未回传分别记录；可读副本不替代原件。

原始流的 digest/sizeBytes 与平台 normalizedText 是不同观察对象。只有证据明确给出实际解码、归一化与 diff.rule，并且该策略覆盖冻结的允许差异时，才能解释“原始字节不同而可比面相同”；归一化后相同不能证明原始字节义务通过。记录未采得/被截断/不可回读的原始范围，不能从一个 digest 还原内容。已确认允许的展示差异不要求模型修成相同；也不能在失败后扩大策略、忽略 stderr 或缩小文件范围求 matched，需要时另冻经确认且平台支持的条件。

coverageRatio、sufficientDimensions 或其他汇总字段按现役平台定义解释，不能单独证明输入送达、预期状态到达或核心路径覆盖。维度 not-applicable 只说明本次未比较，不证明没有 API 调用/副作用或隔离已满足。驱动失败标记/专用退出码只作线索，未有合法来源的执行与观察证据时不据此推定程序实际运行；不新造平台字段或 Agent 比较器。

差异先分转换引入、源已有、环境、装置。只有源/目标定位证据支持转换引入才进入有限模型修复。路径回显/工作目录等装置差异保留两侧原文和平台原判，不自行将 FAIL 改 PASS；请求平台按确认条件重评。装置缺陷的原 job 保留，修正后另记 job，不能改写原始记录。修复预算和停止条件只见[单项闭环](../workflow/conversion-evaluation-loop.md)。

### 5.2 功能比较统计的集合与单位

在既有 result/批次 summary 中注明统计快照、对象单位、精确版本与策略、实际覆盖和依据，不新增运行工具或 Controller 字段。统计消费 §5.1 的有效性与允许关系，而不是重判原标签。

| 单位/集合 | 统计规则 |
|---|---|
| 功能任务集合 | 按唯一 taskId 的当前交付 run/目标版本及适用条件取对应证据；保留全部中间稿/失败 job，但不选最好一次或重复计重提。不同策略/范围分别列集合，不借旧版本 PASS |
| 有效 matched 集合 M | 精确版本、输入/状态/观察、保护项及适用 oracle 均有依据，原 behaviorVerdict=matched；单列名单与覆盖 |
| 有效 semantic_pass 集合 S | 同样有有效依据，原 behaviorVerdict=semantic_pass，允许差异/实际规则有冻结支持；单列名单、依据及覆盖，不降成失败或混同完全字节相同 |
| 冻结范围功能比较通过小计 | M 与 S 互斥，计数为 M 中任务数 + S 中任务数；只是所列范围的比较通过数，不是全批转换成功率或完整业务证明 |
| 差异、不可判定、未评估/缺证据 | 按实际原标签与采信缺口单列；无效 matched/semantic_pass、装置失败、仅编译、未知版本或未覆盖关键义务不进入 M/S。有独立 oracle 结果但平台比较 partial/inconclusive 时分别报告，不改平台 verdict 凑小计 |
| 维度统计 | dimension status=matched/semantic-match 且 applicable、observed 时可列配置比较通过维度小计及两类数量；一个任务的多个维度不变成多个任务，coverage/sufficientDimensions 不证明输入/业务有效 |
| 交付、构建、执行、安全与生命周期 | 另列自己的证据/分母；DONE、build completed/0、source-only baseline PASS、closure complete 或 report.codeVerdict 不直接增加功能任务通过数 |

原标签分布与有效性分类分开保留，同一快照同一任务只归一个当前功能类别；缺阶段或状态身份单列不可映射，不能用补零或净额抵消缺档。人读摘要没有 comparison 维度明细时不从 coverage 反算 semantic-match；现役 JSON matchedDimensions 的含义以实际 schema/实现为准，不能擅自把它改为 matched+semantic-match。统计与真实版本、重复/遗留对账按批量工作流，未确认的部署候选不作当前服务能力。
