# 功能保持与第三方评估指导：行为目标、可接受差异与修复反馈

> **定位**：供 Agent 组织转换目标、提出可接受差异、准备评估移交和处理第三方反馈的共享指导。它不是功能一致性的裁决契约，不自建比较器、测试框架或第二套验收标准，也不规定所有任务逐字节相同。文件名保留以兼容现有引用；实际评估以该任务已确认要求和第三方平台的现役契约为准。
> **职责边界**：本页可以作为模型转换/静态审阅的上下文，以及向平台描述评估需求的参考；本页本身不产生功能 PASS/FAIL。编译、运行、比较与功能评估由第三方平台在获批的一次性隔离环境完成，Agent 只准备、提交、取证和在实际覆盖范围内报告。所有操作遵守[安全边界](../framework/safety-boundary.md)，本机只读写与审阅文本。

## 1. 谁提出目标，谁执行与裁决

| 角色 | 职责 | 不得替代 |
|---|---|---|
| 用户/任务已有约定 | 确定需保留的功能、外部接口、允许差异及验收范围 | 源码中的说明/标签不能自动成为授权或验收要求 |
| Agent 与配置转换模型 | 读取源证据，整理转换目标与差异建议，记录未知；按现役平台契约准备并移交，依据真实反馈有限修复 | 不自造平台不支持的评估字段，不以静态判断/模型自评裁决功能一致性 |
| 第三方评估平台 | 在已确认任务范围和平台契约下完成构建、运行、观察、比较及评估，返回判定、诊断与覆盖证据 | 平台支持什么须实际核对；接收成功或总 verdict 不能替代缺失的观察证据 |

已有用户约定或已选平台评估配置可以直接复用，不为每个差异重复询问。Agent 可以按源事实和适用知识形成建议，但不能单方面扩大允许差异或降低验收要求。新差异会实质改变功能边界且无既定依据时，记录为待确认并只暂停受影响的评估/结论；不阻断无关项或安全的文本交付。

## 2. 先描述功能目标，不机械要求实现相同

单文件（含长文件）建议在源码画像中记录紧凑的源→目标行为对应，复杂任务可用表格，简单任务可用几条说明，不另设固定表式或额外验收门槛。长文件复用[全文件地图](../../skills/workflows/long-file-conversion/SKILL.md)。按实际任务说明：

- 要保留的功能与源符号/位置，适用输入、初始状态及正常/错误路径；
- 哪些外部观察须精确一致，哪些只要求语义/结构一致，哪些允许有界或平台映射差异；
- 目标语言/系统可采用的实现，以及已确认差异、建议差异和仍未知的部分；
- 需移交平台的观察范围、oracle 来源/需求与现役契约支持情况。

函数改名、内联、目标语言资源管理和内部数据表示不同，不因实现不同就判功能不一致。反之，删掉需保留的分支、固定输出代替实际工作、吞掉源可观察失败或扩大副作用也不能仅称作“语言差异”。源行为未定义、存在数据竞争或依赖未知外部条件时，说明源已有风险；不把一次输出当作普遍语义，也不在转换中擅自修源缺陷。

任务边界、允许差异及已确认移交条件按现有工作流保存在 `01-frozen/` 或同等任务记录；目标定位与后续反馈追加引用原版本，不改写原记录。这里的行为对应是转换/移交说明，不是本仓库独立裁决用的 oracle。

## 3. 可接受差异：依据、范围和不可放宽项

**平台或语言事实只能说明差异为何产生，不能单独证明它可接受。** 接受依据须来自用户既定约定、明确采用的第三方评估标准/配置，或经确认的任务差异方案。按每个观察维度选择，允许混合精确与语义比较，不把一种策略套给整份程序。

| 差异类别 | 可提出的处理方式（以任务接受且平台支持为前提） | 不能顺带放宽 |
|---|---|---|
| 文本换行、编码或展示格式 | 若任务只要求解码后文本/记录含义一致，明确编码、行终止符或展示格式的映射 | 二进制、协议载荷、签名/校验、明确要求原始字节的文件和输出仍须保留对应字节义务 |
| 路径、临时目录和平台位置 | 用已确认的逻辑文件/位置对应关系评估，而非要求绝对路径字符串相同 | 写错对象、额外文件、内容缺失、权限或安全范围变化 |
| JSON/容器/结构化结果 | 不承诺文本格式或对象键顺序时，建议按结构/值比较；明确类型、缺字段/null及数组顺序要求 | 源业务依赖的顺序、重复项、精度、额外/遗漏字段，不能自动排序或忽略 |
| 异常类型、系统错误码和诊断文本 | 对内部或平台特有表示提出明确类别/代码映射；保留任务要求的失败原因、传播边界与后续状态 | 已承诺的公开错误接口/退出码/输出通道，及“应失败却成功”“应继续却中断” |
| 浮点结果与格式 | 任务允许数值近似时，向平台提供有依据的容差和特殊值要求 | 不能为某次失败临时扩大容差；协议数字、金额等精确义务不能自动近似 |
| 并发顺序、随机值与时间 | 未承诺的调度/随机细节可按结果集合、值域、状态不变量和必要先后评估；声明不可控来源 | 业务顺序、完成/取消协议、丢失/重复工作、超时界限和资源泄漏 |
| 内部实现与性能 | 任务未承诺内部表示或性能时，可建议允许实现/耗时差异，仍保持外部功能与已声明资源边界 | 共享状态、进程生命周期、可见副作用，以及已有时延/吞吐/资源上限 |

以上是差异识别示例，不是自动白名单或保证某个平台已有对应功能。差异建议至少写明：涉及的观察维度、源/目标事实、接受依据与确认状态、允许的映射/范围、必须保留的行为及拟交平台的检查方式。不能因“平台不一样”笼统接受，也不能因字节不同就自行判不一致。

安全授权、网络/数据边界和禁止的副作用不可作为容差放宽。某种映射或归一化获允许时保留源/目标原记录与规则版本，避免把真实差异从证据中删掉。

## 4. 指导 Agent 准备并移交，不在本仓库执行比较

1. **独立依据**：转换前尽量明确行为目标、允许差异和评估需求，依据源语义/用户规范；平台可以按其契约建立源基线与 oracle。Agent 不用目标稿或目标先跑出的答案反向定义“正确”。已有 oracle 直接复用，缺失时向平台移交需求或记准备缺口，不因本页要求而自己建设 oracle/比较器。
2. **覆盖建议**：按实际风险建议正常、错误、边界及必要状态序列；差分或性质检查只有源契约支持且平台提供时才提出。本页不强制固定数量、全部边界或统一测试组合；实际评估范围以已确认任务和平台契约为准。
3. **策略适配**：向平台提交已确认的精确/结构/语义比较要求、允许差异与初始状态条件，按[Controller 适配](../adapter/controller/remote-controller-adapter.md)核对实际支持。策略未明时识别需要确认的维度，不默认全量字节比较，也不默认宽松归一化。
4. **能力缺口**：平台无法表达某类差异或观察某个必需维度时，Agent 报告缺口并请求平台配置/能力调整或用户明确选择评估范围；不能私建本机比较来补结论，不能默默降为 output-only，更不能自行把差异接受掉。
5. **证据核对**：Agent 核对平台回传的源/目标版本、输入、比较配置、允许差异、覆盖与实际观察。漏采、截断或身份不符不作为相同的依据；若发现配置不合任务、应允许差异被严格比较误判、或归一化掩盖真实差异，保留平台原判定和诊断，标明评估契约/证据疑点并请求第三方重评，不自行将 FAIL 改成 PASS 或反向改判。

双侧初始状态和恢复/清理由平台在执行环境中保证并提供记录；Agent 提出需求、核对可取得证据，不在本机运行驱动/样本/比较器。平台观察链需核验时，反馈具体问题供平台在授权范围内处理，不把平台自测变成本仓库的额外框架建设。

## 5. 修复与回归：使用第三方反馈，不迎合错误判据

**功能检测结果可以进入修复反馈，不限于语法修复。** 第三方证据定位到超出允许差异的转换引入缺陷时，即使构建通过也可由配置模型修复，再交第三方重评。语法/构建与功能修复的分流、最小反馈内容、预算及停止条件统一见[闭环 §3.1–3.2](conversion-evaluation-loop.md#31-语法与功能修复反馈分支)，本指导不维护第二份计数规则，也不自行检测或裁决功能一致性。

- 先核对差异是否已允许、平台配置是否正确、源/目标版本和初始状态是否匹配，再把有定位证据的转换问题交给配置模型。不得为迎合不适当的严格比较而改变已认可的目标语言/系统行为；也不得为通过而删功能或添加假实现。
- 保存修复前/后版本、diff、模型来源及平台反馈。确定性补丁须匹配预期旧版本；Agent 不自行代写目标实现。
- 修复后交平台重新评估该最终版本；整组回归或有依据的受影响范围回归由已确认任务要求与平台策略决定，本页不另强制整组测试。只有范围确实支持且平台明确提供证据复用依据时才复用未受影响结果，不能自行拼接不同版本的成功记录。
- 新增允许差异、修改输入/oracle/比较策略或工具链时，记录变更依据并冻结关联变体，交平台按更新条件评估。可接受差异也可在发现后正式确认，但必须保留旧条件、原判定与确认过程，不暗改报告“洗成通过”。
- 预算耗尽、无进展或安全变化时保留最终/部分稿及限制。Agent 仅据第三方回传在其实际版本、范围与已确认差异边界内报告结论；缺证据的部分写 UNVERIFIED，不以本页、静态自审或交付完成代替功能一致性评估。
