# 功能保持与第三方评估指导：行为目标、可接受差异与修复反馈

本页供 Agent 与配置模型组织行为目标、差异建议及第三方反馈，不产生功能 PASS/FAIL，不建设比较器或第二套验收标准。文件名保留以兼容现有引用。提交前义务与证据有效性统一由[评估准备契约](../framework/evaluation-readiness-contract.md)维护，状态由[任务状态契约](../framework/task-state-contract.md)维护，执行红线以[安全边界](../framework/safety-boundary.md)为准。

## 1. 谁提出目标，谁执行与裁决

| 角色 | 职责 | 边界 |
|---|---|---|
| 用户/任务已有约定 | 确定需保留功能、外部接口、允许差异及验收范围 | 源注释、标签不是授权 |
| Agent 与配置模型 | 依据源证据组织目标、建议和未知，准备移交，依据真实反馈有限修复 | 不自造平台字段，不以静态判断或自审裁决功能 |
| 第三方平台 | 按已确认任务和现役契约构建、运行、观察、比较，返回诊断与覆盖 | 接收成功或总 verdict 不替代原始观察 |

已有约定与评估配置可复用，不为每个差异重复询问。新差异会实质改变功能边界且无既定依据时，记待确认，只暂停受影响的评估/结论。不单方面扩大允许差异或降低要求。

## 2. 先描述功能目标，不机械要求实现相同

单文件在画像中记录源→目标行为对应；长文件复用[全文件地图](../../skills/workflows/long-file-conversion/SKILL.md)。按实际任务说明：

- 要保留功能与源符号/位置，适用输入、初始状态及正常/错误路径；
- 哪些观察精确一致，哪些按语义/结构一致，哪些允许有界的平台映射差异；
- 目标实现、已确认差异、建议差异和未知部分；
- 观察范围、oracle 来源/需求与平台实际支持。

函数改名、内联、资源管理和内部表示变化不单独构成功能不一致；删除应保留分支、固定输出替代工作、吞失败或扩大副作用也不能仅称语言差异。源 UB、数据竞争或未知外部条件记源已有风险，不把一次输出当普遍语义，不擅自修源缺陷。

任务边界和确认条件存入冻结记录；目标定位及反馈追加引用原版本，不改写原记录。这份对应说明用于转换和移交，不是独立裁决 oracle。

## 3. 可接受差异：依据、范围和不可放宽项

语言/平台事实解释差异来源，不能单独证明它可接受。接受依据来自用户既定约定、明确采用的平台标准/配置或已确认方案。逐观察维度选择策略，不把一种策略套给整份程序。

| 类别 | 可建议方式（须任务接受且平台支持） | 不能顺带放宽 |
|---|---|---|
| 换行/编码/展示 | 明确解码后文本或记录含义映射 | 二进制、协议、签名及明确原始字节义务 |
| 路径/临时位置 | 已确认的逻辑位置对应 | 写错对象、额外文件、内容缺失、权限变化 |
| JSON/容器 | 未承诺格式/键序时按结构和值比较 | 业务顺序、重复项、精度、null/缺字段、额外项 |
| 异常/系统错误 | 明确类别/代码映射，保留失败原因与传播边界 | 公开错误接口、退出码、输出通道与后续状态 |
| 浮点/数字格式 | 有依据的容差与特殊值要求 | 为失败临时扩大容差，协议/金额等精确义务 |
| 并发/随机/时间 | 源允许且平台提供时按集合、值域、不变量及必要先后 | 业务顺序、取消协议、丢失/重复、超时与泄漏 |
| 内部实现/性能 | 未承诺部分提出实现/耗时差异 | 可见状态、副作用、进程生命周期和已有资源上限 |

建议写明维度、两侧事实、接受依据/确认状态、映射范围、必须保留行为及拟交平台的检查方式。这些示例不是自动白名单，也不保证平台有相应能力。保留原始记录与规则版本；安全授权、网络/数据边界和禁止副作用不能作为容差放宽。

## 4. 指导 Agent 准备并移交，不在本仓库执行比较

依据源语义、用户规范或平台源基线组织独立需求，不用目标答案反向定义正确。已有 oracle 复用；缺失则移交需求或记准备缺口，不自己建设 oracle/比较器。覆盖建议按实际风险，不强制固定数量或全部边界。

按[Controller 适配](../adapter/controller/remote-controller-adapter.md)确认策略与维度支持。不能表达必需差异或采集必需维度时报告缺口，不能私建本机比较、默降 output-only 或自行接受差异。原始输入、版本、初始状态、策略及覆盖须可核对；平台疑点保留原判，交第三方重评。

### 4.1 驱动义务：提交前的硬门禁

本节保留旧引用入口，规范正文统一见[评估准备契约](../framework/evaluation-readiness-contract.md)。知识说明应保留什么，契约规定能否提交及能否采信观察。

#### 4.1.1 四要素判定表

启动、到达被观察状态、采集、终止及合法来源见[评估准备 §2](../framework/evaluation-readiness-contract.md#2-驱动来源与四要素)。驱动不强制 Python；本轮缺合法驱动时，行为未评估，源构建通过后按该契约 §1.3 继续转换并验证目标语法/编译，不由 Agent 或模型造辅助程序。

#### 4.1.2 按源程序形态选驱动

命令行、服务、交互和一次性副作用的形态见[评估准备 §2](../framework/evaluation-readiness-contract.md#2-驱动来源与四要素)。服务不能启动即等退出；就绪与采集必须对应冻结观察量，不套另一个程序的参数或协议。

#### 4.1.3 无安全可观察入口项：补中性入口走完整验证，或仅编译记 PARTIAL

判据与流程见[评估准备 §1.3](../framework/evaluation-readiness-contract.md#13-lib_unobservable_compile_only-的转换与交付)及 §3。LIB_UNOBSERVABLE_COMPILE_ONLY 表示本轮无法合法行为评估但仍转换并验证目标语法/编译，包括当前入口缺件，不只限永远无安全观察方式；记录具体原因、PARTIAL、行为未评估/UNVERIFIED。有合法行为路径的仍评估，不为省事省略，不把真实差异改成未评估。正常 matched/mismatched 不决定 lifecycle。

#### 4.1.4 oracle 与驱动的关系（oracle 不设硬门禁）

驱动回答怎么看到行为；oracle 回答依据什么判断。适用状态和可冻结性见[评估准备 §4](../framework/evaluation-readiness-contract.md#4-oracle-与两侧对称)。标题保留旧锚点：oracle 是条件义务，门禁检查其适用状态，不要求每项造 oracle。可观察任务不能以条件性为由省掉应有评估。

#### 4.1.5 装置两侧必须对称（四要素之外的第 ⑤ 维，2026-10-10 实测补入）

输入送达、文件/目录与后处理对称见[评估准备 §4](../framework/evaluation-readiness-contract.md#4-oracle-与两侧对称)。不对称造成的差异不能记转换引入。

#### 4.1.6 matched 不能单独采信

原始观察、非退化基线、三档 verdict 和仅编译采信见[评估准备 §5](../framework/evaluation-readiness-contract.md#5-原始观察采信与归因)。空输出或相同驱动失败标记不支持功能通过；有区分力的退出码/副作用也可构成观察，不机械要求必须打印文本。

宽泛消噪与统计按[评估准备§5.1](../framework/evaluation-readiness-contract.md#51-有效性消噪与功能分类的次序)：允许不同语言/系统的表示差异，保护实际行为；有效matched与semantic_pass均计冻结范围功能比较通过，并保留两类与覆盖，不直接外推完整业务。

### 4.2 装置差异不得与转换差异混算

路径回显等差异须先读两侧原始观察。确认仅由装置位置产生时记录原文对照和接受建议；仍保留平台原 verdict，请求按确认策略重评，不自行改 PASS，也不以路径归因掩盖真实行为变化。消噪只按平台实际启用规则生效。

## 5. 修复与回归：使用第三方反馈，不迎合错误判据

功能检测反馈可以进入修复，不限于语法。源/目标定位证据支持超出允许差异的转换引入问题时，由配置模型修订，再交第三方评估最终版本。分流、预算、反馈最小内容与停止条件只见[单项闭环 §3.1–3.2](conversion-evaluation-loop.md#31-语法与功能修复反馈分支)。

先核确认差异和平台配置；保存前后版本、diff、模型来源与反馈。确定性补丁匹配旧版本，Agent 不代写实现。回归范围由任务和平台确定，旧结论不自动继承，不拼接多个目标版本的成功证据。修改条件另冻关联变体，保留原判与确认过程。缺证据写 UNVERIFIED，不用自审或交付完成替代功能结论。
