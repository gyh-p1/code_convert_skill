# 转换—自审—第三方评估闭环

> 状态：可复用工作流约束，不证明转换效果，不提供本机执行许可。
> 任务模式由[根入口](../../SKILL.md)确定；产物与字段由[交付契约](../framework/delivery-handoff-contract.md)维护；执行红线以[安全边界](../framework/safety-boundary.md)为准。本页不依赖测试数据集或开发期报告。

## 1. 冻结输入与执行边界

首次模型请求前冻结源快照/哈希、源与目标语言及 OS、架构/ABI、实际条件分支、目标标准/工具链/SDK、依赖、任务模式、所选知识快照、非敏感模型参数、允许差异及禁止副作用。行为比较须另冻结输入、可观察义务和独立 oracle。密钥不入提示、日志、manifest 或交付。

片段只在声明上下文中检查语法，不强制补可运行入口。单文件默认使用本工作区已授权的双侧评估形态；无入口时按任务契约补最小中性驱动并冻结内容，不补造真实框架/业务实现。知识审阅、文档修改或明确文本-only 的任务不因此触发模型转换和动态评估。

已确认的批次授权可复用，不逐项重复询问是否评估；**已有授权、服务可达、runner READY、逐例安全隔离是不同条件**。提交前仍核对实际入口、工具链、数据/网络范围与清理。硬编码外部地址须先在 VM/网络层阻断或重定向并验证隔离，READY/快照不证明无外联。条件未满足暂不提交；不改用本机执行。

同一 run 改模型、工具链、OS 或 oracle 不算同条件重试，另起版本/run 记录差异。模型不可复现时记录实际返回名与非确定性限制。

## 2. 阶段及门槛

| 阶段 | 动作 | 推进或停止 |
|---|---|---|
| FROZEN | 核对输入、适用知识、安全与模型配置；长文件建行为/符号地图 | 关键信息缺失时写假设/待确认，不虚构冻结事实 |
| GENERATED | 保存原始模型响应、目标版本、参数与用量；检查空响应、截断、文件集合及关键分支 | 完整才自审；传输/解析失败不是代码 repair 或自审通过 |
| SELF_REVIEWED | 配置模型对照源、目标、冻结契约和适用知识作结构化自审 | 无未解决可定位转换问题且记录完整，才可作为内部预检；不是编译结论 |
| SELF_REPAIRED | 配置模型据定位证据生成新稿/确定性补丁，再复审 | 默认最多两次自修；持续冲突、重复失败、截断或预算耗尽且仍有确认问题则部分交付 |
| EVALUATION_READY | 范围预检、精确源码/目标哈希、构建/运行命令、输入/oracle、授权和隔离核对；按消费方契约组装 | 已授权且全部门槛满足直接提交；不因文本审查指令而提交样本 |
| EVALUATED | 保存 job 回执、原报告、双侧 build/execution/comparison、环境/清理及版本身份 | 按 §3 分层，不将综合 verdict 当作语法结果 |
| REPAIR_AFTER_EVAL | 可定位代码/行为问题交配置模型，复审后在相同冻结条件重评 | 默认最多两次评估后 repair；无进展、证据不足或安全变化则停止 |
| CLOSED | 交付最终/部分稿、必要过程记录与分层结论 | 未验证不写通过，未决项/限制明示；关闭不等于验收通过 |

**计数**：首次自审是第 1 次，自修一次后的复审通常是第 2 次，两次自修后通常是第 3 次。reviewN 不等于 selfRepairRounds；以实际修订版本/内容核对。传输重试不计代码修复但计用量。任务可以预先冻结其他有限预算；达到预算仍有问题时记 SELF_REVIEW_UNRESOLVED，不通过补记理由无限修复。

**响应完整性**：必要时改为逐文件分块 `<<<FILE: 相对路径>>>` … `<<<END FILE>>>`，仅改变封装，记录失败原文与协议切换。拒绝绝对/越界路径、重复路径、缺结束标记、空正文或无法解释的标记外源码；不把 HTTP 成功或思考文本当目标代码。新代码只能来自配置模型，Agent 仅机械应用其确定性补丁并记来源。

同一冻结请求因传输、截断或解析失败可重试一次；两次尝试和用量均保存。仍不完整就停止该轮并报告，不将重试计为代码自修，也不暗中切换模型或工具链。

产物命名和实际目录指针按[交付契约 §2.2](../framework/delivery-handoff-contract.md)；不要改写已冻结输入或原评估报告。

## 3. 证据判读与失败分流

先核对 report/evidence 的 job、case、role、输入/目标版本与工具链，再读取**对应侧的 build**。build.status=completed 且 exitCode=0 才支持编译 PASS；已实际构建且非零退出支持 FAIL；未构建、跳过、基础设施故障或证据不足为 UNVERIFIED/无法判定，不能反推代码错误。编译、链接、启动、行为、安全分开。

1. 基础设施、缓存/权限、runner 或清理污染故障：环境归因，不让模型改代码绕过；恢复后同条件重提。
2. 工具链/契约不匹配：先修环境/命令；切换 SDK/编译器/构建分支另冻版本，不伪造预定义宏冒充另一工具链。
3. 源 build/基线执行失败：无可比源基线；目标若有独立 build 仍据实分列，不能把源失败算目标失败。
4. 目标代码 build 失败：保存命令、stderr、退出码、目标哈希；可定位原因交配置模型修订。
5. build 成功但运行失败/行为不同：不能记语法错误；按冻结 oracle 找差异，核对源已有问题/转换引入/契约允许差异。
6. 维度匹配：只报告实际输入与观察范围；驱动 stdoutLen 等摘要不能替代原程序字节/事件 oracle。

未开展为 NOT_STARTED，缺依赖/版本/oracle 写具体准备缺口；入口超隔离范围为 RUN_SAFETY_NOT_READY。只有实际环境故障有诊断才 BLOCKED_ENV；“本机禁止执行”不是远端环境故障。

项目当前质量阶段只统计最终版本编译结论；任务若另有正式行为证据，仍按其 oracle 限定范围报告，不从编译或自审推断功能等价。

## 4. 自审最小契约

回答完整性、关键声明/入口/分支覆盖、可定位类型/API/调用/平台/资源/输出疑点及来源、建议修改或无需修改、修改风险。结论为 REPAIR-RECOMMENDED 或 NO-REPAIR-IDENTIFIED。位置、evidence、origin、proposed_fix/无需修改、risk 均须明确；空/截断、正文与结论矛盾、无编译证据断言语法通过均不是有效预检。

### 4.1 来源与字段容错

| origin | 含义与处理 |
|---|---|
| conversion-introduced | 有源/目标定位证据的转换引入疑点，先核实再修 |
| source-preexisting | 源已有风险，登记并保留原契约语义，不顺手修复 |
| toolchain-unknown | 依赖指定工具链/SDK 才能判定，不能冒称 compiler 诊断 |
| environment | 环境/基础设施问题，不当代码缺陷修复 |
| undetermined | 已尝试但证据不足，必须写缺哪份证据 |

自审标签不是缺陷真值。判读链为本任务源快照→被审阅目标版本→实际诊断/观察→官方依据交叉核对；不能只凭某轮自审或文档存在就宣称任务已验证。

原 self-review 文件一经保存不事后补字段。缺失/矛盾记录仍保存，另写追加裁决引用原路径/哈希、条目、源/目标版本、依据、有效来源和未知项；不能删除问题或猜填来源使统计好看。原记录单独不能作通过凭据；必要时在有限预算内由配置模型重新自审，未解决可定位问题仍阻断内部预检。**无需改动不等于源缺陷**，未知来源不等于转换引入。

### 4.2 轮次冲突

与上一轮相反或建议撤销修订时，显式引用旧条目和目标变更，给出可核对依据，记录采纳本轮/维持前轮/无法裁决。无依据不得静默采纳后者或撤销既有修订；保持未知并按停止条件处理。后轮“无问题”不覆盖独立编译诊断，前轮建议也不能未经核实变成通则。

## 5. 范围对账预检

预检只提示疑点，不给语法/行为 PASS，不替代第三方 build。逐项对照冻结方向、允许移除/重构部分、预期符号/分支和源目标语义地图：

- 源目标高度相似：只有契约要求转换的构造仍未映射才提示。**合法 C 子集可直接是合法 C++**，不要求为了“有目标语言特性”改写；空白/注释差异也不证明已转换。
- 整块缺失：核对允许移除的平台分支与同义内联/重命名，不能只比较原符号名集合判漏译。
- 源构造残留：先确认它是否也在目标中合法同义，或是否只是字符串/注释/嵌入载荷；不按关键词计数直接裁决。

提示保存在新的预检记录，不改冻结输入。启发式命中不自动阻断；回查确认问题后仍走 §2 的有限模型修订门槛，不以“不延迟 build”为由绕过未决缺陷。

## 6. 可复核的规则改进

知识可从具体任务反馈提炼，但规则本体只维护触发、前提、映射边界、反例、未知与官方依据，不承载测试数据集索引。开发试验若验证规则效果，须确认它确实被加载/触发；用固定源/契约/工具链/模型/oracle 与独立知识快照，只改变待验规则，记录非确定性限制。自审条目消失只是诊断，编译/行为义务须独立验证。

测试材料按该次交付约定保留或清理；没有证据的历史结论不再作为可复核能力保证。正在执行/未收尾的任务仍须保留恢复所需记录，不能提前删除或覆盖。

## 7. RAG

默认关闭，只在单独批准的检索试验中启用。检索片段保留来源、版本/适用条件、查询、注入位置与 token 成本；不注入其他 run 的目标代码、不替代核心约束/自审/build/oracle。对照固定模型、知识主体、工具链、输入、oracle 和有限修复预算，仅改变检索/注入；成本、语法、行为、来源正确性分列，不凭少量试验外推。
