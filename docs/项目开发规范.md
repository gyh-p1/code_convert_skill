# 项目开发规范

> 状态：ACTIVE（当前项目规范）  
> 更新：2026-09-25  
> 适用：本项目文档、Skill 与按需添加的辅助工具

## 1. 目标与现状

本项目是给智能体使用的转换知识 Skill，不是独立转换平台。业务定位、片段/单文件质量目标、700 个物理源代码行计划上限和当前能力以 [项目业务文档和能力边界](项目业务文档和能力边界.md) 为唯一真源。当前方向知识仍处于初稿阶段；已批准规划一次受控的四例无 RAG/RAG 探索比较；C01 run-02 已完成一次用户授权的隔离 VM 探索 comparison，但四例基线所需样例筛选、统一工具链与 oracle、隔离方案仍未准备完成；长文件工作流已有初稿但未经转换验证，不能把该计划写成已运行或已验收。

## 2. 工作方式

- 每项改动说明目标、范围与非目标；区分当前事实、目标设计、计划与验证证据。
- 修改前检查入口、相关 Skill、链接、旧资料来源及未提交改动；不覆盖或运行来源不明资产。
- 只为当前需求创建文件。出现真实重复/检索瓶颈时再提取机制；不预建完整运行时、发布体系或空目录。
- 试验样例、环境、行为 oracle 和变量控制必须先按 `docs/stages/` 确定；执行遵循 `docs/安全边界.md`。路线批准不代表任意样例都获准运行。

## 3. 单一真源与依赖

- `项目业务文档和能力边界.md` 规定业务与能力；根 `README.md` 导航；根 `SKILL.md` 是平台无关入口；本文件管项目协作；`Skill编写规范.md` 管知识写法；`安全边界.md` 管样例与执行边界。
- Codex 的 `.agents/skills/code-convert/SKILL.md` 只负责发现并链接根入口。其他平台按自身发现方式增加薄入口，不复制转换知识。
- 语言方向、实际语义场景、source OS → target OS 和任务模式各有职责。ATT&CK 是分类元数据，不默认扩展为独立规则文件。
- 新增、移动或删除知识时同步更新真实入口与引用；不从旧仓库的实现或验证状态推断本项目能力。

阶段计划唯一入口：[docs/stages/README.md](stages/README.md)。阶段文档是计划/试验设计，不取代当前业务规范。

## 4. 验证与完成说明

- 转换调度遵循 `references/conversion-evaluation-loop.md` 的阶段门槛、有限自修/repair 预算和第三方失败分流；Skill 只约束流程，不声称随机模型输出因此确定。\n- 文本审阅、Skill 格式检查、链接检查、语法检查、功能行为试验和检索评估是不同证据等级，必须分别报告。
- 片段任务关注语法，不要求独立运行；单文件任务另需行为 oracle。模型自评、代码相似度、RAG 命中都不能单独证明功能正确。
- 无 RAG 与 RAG 对照固定模型、提示主体、Skill、样例、环境与 oracle，仅改变是否检索/注入知识；四例结果限于试点样本。
- 700 个 LF 归一化物理源代码行是待验证支持上限；性能指标须另定义 token、时延等口径。
- 交付列明实际改动、执行过的检查、未检查项、逐例不确定性。不宣称证据未覆盖的准确率、等价或安全保证。

## 5. 文件与安全

文件名清晰；Skill 目录使用小写连字符。不要提交真实凭证、个人信息、受限源代码或环境状态。涉及执行、删除或难恢复副作用时，先检查精确目标与授权；风险超出已批准试验边界时暂停并说明。
