# 项目开发规范

> 状态：ACTIVE（当前项目规范）  
> 更新：2026-09-27
> 适用：本项目文档、Skill 与按需添加的辅助工具

## 1. 目标与现状

本项目是给智能体使用的转换知识 Skill，不是独立转换平台。业务定位、片段/单文件质量目标、700 个物理源代码行计划上限和当前能力以[项目业务文档和能力边界](项目业务文档和能力边界.md)为唯一真源。C01 run-02 曾完成一次授权隔离 VM 探索 comparison，有限 oracle 只覆盖五个固定 loopback 请求的输出，不是正式基线。当前按[最终交付编译质量与 Skill 拓展](stages/final-output-compile/阶段方案.md)推进；原固定四例无 RAG/RAG 计划已[取消](stages/four-case-cancellation.md)。长文件工作流已有初稿，但 700 行范围及广泛转换效果均未验收。

## 2. 工作方式

- 每项改动说明目标、范围与非目标；区分当前事实、目标设计、计划与验证证据。
- 修改前检查入口、相关 Skill、链接、旧资料来源及未提交改动；不覆盖或运行来源不明资产。
- 只为当前需求创建文件。出现真实重复/检索瓶颈时再提取机制；不预建完整运行时、发布体系或空目录。
- 编译质量试验先冻结样例来源、目标工具链、检查上下文、执行边界和评估契约；重新开展功能/RAG 试验时再冻结行为 oracle 和对照变量。执行遵循 `docs/安全边界.md`。路线批准不代表任意样例都获准编译或运行。

## 3. 单一真源与依赖

- `项目业务文档和能力边界.md` 规定业务与能力；根 `README.md` 导航；根 `SKILL.md` 是平台无关入口；本文件管项目协作；`Skill编写规范.md` 管知识写法；`安全边界.md` 管样例与执行边界。
- Codex 的 `.agents/skills/code-convert/SKILL.md` 只负责发现并链接根入口。其他平台按自身发现方式增加薄入口，不复制转换知识。
- 语言方向、实际语义场景、source OS → target OS 和任务模式各有职责。ATT&CK 是分类元数据，不默认扩展为独立规则文件。
- 新增、移动或删除知识时同步更新真实入口与引用；不从旧仓库的实现或验证状态推断本项目能力。

阶段计划唯一入口：[docs/stages/README.md](stages/README.md)。阶段文档是计划/试验设计，不取代当前业务规范。

## 4. 验证与完成说明

- 转换调度遵循 `references/workflow/conversion-evaluation-loop.md` 的阶段门槛、有限自修/repair 预算和第三方失败分流；Skill 只约束流程，不声称随机模型输出因此确定。
- 文本审阅、Skill 格式检查、链接检查、语法检查、功能行为试验和检索评估是不同证据等级，必须分别报告。
- 片段任务关注声明上下文中的语法，不要求独立运行；单文件的长期目标仍包括功能保持，但当前阶段只统计最终交付版本的编译结果，功能记为未评估。模型自评、代码相似度、RAG 命中或编译通过都不能单独证明功能正确。
- 首次生成及中间修订的失败原因、次数和修订后通过仅供 Skill 开发诊断，不进入产品质量指标；不得将修订稿通过回写成原稿通过。报告有效任务、可判定编译结果、环境/依赖故障和未验证数。
- 原固定四例无 RAG/RAG 对照已取消。未来若另立检索试验，先冻结新问题、样本与评价口径；单变量比较时固定模型、提示主体、Skill、环境与 oracle，仅改变是否检索/注入知识。
- 700 个 LF 归一化物理源代码行是待验证支持上限；性能指标须另定义 token、时延等口径。
- 交付列明实际改动、执行过的检查、未检查项、逐例不确定性。不宣称证据未覆盖的准确率、等价或安全保证。

## 5. 文件与安全

文件名清晰；Skill 目录使用小写连字符。不要提交真实凭证、个人信息、受限源代码或环境状态。涉及执行、删除或难恢复副作用时，先检查精确目标与授权；风险超出已批准试验边界时暂停并说明。

## 6. 阶段步骤：先方案后实施与进展追踪

阶段计划（为什么做、要达到什么）仍写在 `docs/stages/` 的阶段方案文件；进入执行的阶段在 `docs/stages/<阶段名>/` 建一个执行目录，承载“每一步怎么做、做到哪了”。保持“阶段方案 + 步骤方案 + 进度入口”这一轻量结构即可，不引入 Spec/Plan/Tasks 三件套、Contract、RunManifest 等平台级机制。

- **先方案后实施**：每一步先写「方案」再动手。方案至少含：目标、纳入与非目标、依赖与前置、预计改动文件、验收依据（可观察证据或人工检查方式）、风险与停止条件。方案未确认前，不改对应的 Skill、文档或数据。
- **确认才实施，不成立就回退**：方案确认后才进入实施；实施中发现方案不成立（目标错、边界错、证据取不到），停下回到方案修订，不在实施里自行改方向。
- **唯一进度真源**：阶段执行目录的 `index.md` 是该阶段进展与方向的唯一真源，记录步骤清单、每步状态、当前执行项、已完成/剩余、最近证据、下一动作和中断恢复位置。聊天输出、提交信息不作为第二套进度。
- **状态词汇**：每步任一时刻只有一个状态——`待定`、`进行中`、`阻塞`、`已完成`、`已取消`。`阻塞`写明解除条件与下一责任；`已完成`链接实际改动或证据；`已取消`写明原因。阶段收尾时步骤只能是 `已完成` 或已确认的 `已取消`。
- **按需创建，不预建空壳**：步骤材料在进入执行时才创建；未来候选步骤只在 `index.md` 列出，不建空文件或空目录。
- **中断恢复**：先读 `docs/stages/README.md` → 阶段 `index.md` → 当前 `进行中` 步骤，从记录的恢复位置继续，不靠聊天上下文猜测。
- **诚实分层照旧**：方案与进度里区分当前事实、目标、计划与验证证据；文本审阅、编译、功能试验是不同证据等级，分别记录（见 §4）。
