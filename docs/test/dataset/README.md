## 本次交付的测试集征集要求（2026-09-29）

测试集负责人先搜集和静态审阅**候选**，不运行不可信源码；正式冻结/执行由项目负责人按[安全边界](../../安全边界.md)和[开发规范](../../项目开发规范.md#35-两周交付冲刺四方分工与接口)把关。既有历史 run 可作选题线索，只有来源、冻结契约及证据满足本次口径时才能纳入本次交付。候选清单留在现有 `docs/test/dataset/`，不另建 candidates/sources 目录或生成 42 个空 case。

### 覆盖目标与计数

- C、C++、C#、Python、Go、PowerShell、Ruby **七种语言 42 个不同的有向源→目标方向**；每项任务只计一个方向，至少为每个方向准备一项可冻结候选；可以复用合适的上游项目，但每项任务须有匹配的源语言与独立的目标方向。方向覆盖只表示案例存在；转换效果须另有运行证据。
- **至少 10 个不同的 ATT&CK Enterprise 战术 ID**，逐类给出源码中具体符号/行为、分类依据、对应转换任务与证据；同一案例可关联多个有证据的战术，但不能仅靠标签把无关代码计入。优先选择能用受控输入和 mock/loopback 观察的安全案例。
- 目标 OS **Windows、Linux、macOS 各至少有一项**，列明目标标准/运行时/编译器或解释器、依赖和 OS 特有行为；一个跨 OS 任务不得默认代表该 OS 上所有方向。
- 至少一项**单次完整源文件不低于 600 个 LF 归一化物理源代码行**的候选；同时记录有效代码行、token 与逻辑密度，不接受填充或拼接无关文件。优先选择 600–700 行以同时落入既有 700 行计划上限；超 700 行候选单列为超计划范围，不能冒充范围内验收。源码和目标要能冻结同一任务的行为义务与 oracle，不能只靠 LOC 和编译。
- 一份可供项目负责人**单批提交不少于 40 项、允许排队**的任务清单。若 42 个方向候选都就绪，可同批提交 42 项同时覆盖方向与批量门槛；如容量不足，40 项批次与余下方向的证据分开报告。40 项队列完成与方向/等价成功率不是同一指标；无需把 42 方向、10 战术、3 OS 做笛卡尔积样本。

### 每项候选的交接字段

1. 稳定上游地址、版本/提交、源文件路径和不可变哈希、许可及复用条件；原创/修改处写清；不得携带真实凭证、隐私或受限代码。
2. 源与目标语言/标准/运行时、源与目标 OS/架构、目标构建或语法检查工具链、依赖及许可、入口/驱动和是否可在隔离环境取得；分别记录源基线和目标检查条件。
3. 实际网络/文件/进程/权限等行为的源码符号或行段、ATT&CK 战术 ID 的分类理由及适用语言/场景/系统 Skill；规则缺口显式写出，不能推断未实现能力。
4. 片段/单文件/长单文件模式，长度计数口径；冻结的输入、预期输出/状态/错误路径/资源或外部副作用，以及能复核的行为 oracle；仅编译可查而行为不可查时标 `UNVERIFIED`。
5. 安全边界：不可信执行风险、受控目标/假数据/loopback 或无外联 fixture、隔离要求、禁止副作用、清理条件；未获准不可运行或声称行为验证。
6. 状态与证据：`候选`、`已冻结`、`已运行` 或 `阻断`；记录负责人、批次/任务 ID、模型与 Skill 版本、最终目标版本、逐项 build/行为结果及诊断路径。环境/依赖失败和代码失败分开，不把历史稿或中间稿计作最终 PASS。

**入选门槛**：字段齐全、来源许可可用、安全可审批、源行为与目标检查路径具体，且能够说明该项补哪个方向/战术/OS 或长文件缺口。否则只保留候选记录与原因，不用低质量样本凑数。测试集负责人交清单和审阅结论，不替项目负责人承诺模型输出或自动评测结果。

## 数据使用边界

当前样例以语法/编译探索和有限受控行为为主，不能代表真实攻防使用效果。数据集中的历史结果不自动继承为当前能力声明；新样例必须先核对上游身份、许可、原件/改写、真实行为和隔离可观测性，并按项目开发规范冻结任务条件。功能检测、运行授权和安全判断不能由本 README 或历史 run 单独授予。
