# 项目业务文档和能力边界

> 文档类型：当前产品定位与能力边界  
> 状态：ACTIVE（本项目业务范围唯一真源）  
> 更新：2026-09-25  
> 读者：项目开发者、接入智能体的开发者  
> 失效条件：被明确确认的新业务定位替代；实现状态变化应原地更新

## 1. 最终业务定位

本项目建设**面向网络攻防相关代码的转换知识 Skill**，由智能体接收指令、读取适用知识，并在本工作区调度 `.env` 配置的外部模型生成目标代码。智能体负责画像、Skill 选择、请求、静态核对和移交，不自行冒称模型输出。Skill 提供语言、行为场景、系统迁移和长代码工作流知识；Skill 本身不是独立转换程序，不负责模型服务或正式等价裁决。

输入任务先区分两种交付模式：

| 模式 | 目标质量 | 不承诺 |
|---|---|---|
| **片段转换** | 在用户给定或明确声明的上下文中，目标片段语法正确 | 可独立运行、完整功能或与完整程序行为等价 |
| **单文件转换** | 目标文件语法正确，并按给定场景与检查依据尽可能保持功能行为 | 未经测试/证据支持的普遍等价保证 |

长单文件是单文件模式的规模子类，需要额外的结构清点和分段一致性工作流。**700 个 LF 归一化物理源代码行是计划支持范围的上限目标，不是当前已实现或已验收能力。**行数是规模/容量边界，不是性能指标；性能若要纳入需求，须另行定义时延、资源或成本测量。试点要求 C01/C02 各有不少于 600 个有效代码行，且不超过 700 个 LF 归一化物理行；LOC 计数口径须冻结，另记录 token 数并检查逻辑密度，避免填充。

## 2. 知识维度与组合架构

任务可组合以下维度；不为维度组合预生成笛卡尔积文件：

1. **任务模式/工作流**：片段、单文件、长单文件；决定转换与审阅流程，不是语言知识。
2. **语言方向**：源语言 → 目标语言，例如 C → C++。
3. **实际语义场景**：源码确有的网络 I/O、文件、进程、凭证接口等行为；可多选，以行为证据为准。
4. **系统方向**：源 OS → 目标 OS，例如 Linux → Windows；同平台与跨平台必须区分。架构、ABI、编译器、运行时/API 版本是相关时的附加条件。
5. **ATT&CK Enterprise 战术**：完整分类/检索元数据；不代替代码行为判断，也不要求每个战术都有专属转换 Skill。
6. **可选知识检索**：未来 RAG 为已选知识补充带来源的候选片段，不凌驾于核心约束。

```text
用户指令与源码
  → 冻结任务契约（源码快照、任务模式、语言/系统方向、架构/工具链、禁止副作用）
  → 静态解读源码并形成画像/符号与行为地图
  → 依据源码证据标记语言、实际场景、source OS → target OS 与 ATT&CK（无证据则 none）
  → 按标签选择语言 + 场景 + 系统 + 工作流 Skill，并记录知识缺口
  → 长文件先完成依赖/资源/行为地图，再调度配置模型转换 → 结构化自审 → 有限模型自修/复审 → 静态核对 →（获批时）第三方编译/行为评估 → 按诊断有限 repair
  → 产出目标代码、result.md 与适用的 evaluator_manifest.json
  → 在审批后的隔离环境分别取得语法/行为证据；未审批时保持 UNVERIFIED
```

知识组合可以作为本次任务的 prompt 上下文供大模型使用，但不保存每种组合的永久合成 Skill。方向负责语言/API 映射，场景负责跨方向行为语义，系统规则负责平台差异，长文件工作流负责全文件一致性；规则冲突或无法映射时指出差异，不把“相似 API”直接称作等价。

## 3. 质量与试验口径

### 3.1 片段

语法正确率需说明检查上下文：完整函数/可独立片段可用目标编译器或解析器的语法检查；依赖外部声明的片段需以用户提供或中性声明桩补足。上下文不足时结果为“无法判定”，不能把不可独立编译的片段判成语法错误，也不能由语法通过推导功能正确。

### 3.2 单文件

记录语法/编译结果与场景级行为检查，分开报告通过、失败和不确定。功能检查依据应在转换前写成可观察行为约束，例如输入输出、协议字节/状态、文件结果、退出码或错误路径；代码相似度或模型自评不能单独充当功能正确 oracle。

### 3.3 长单文件

计划上限为 700 个 LF 归一化物理源代码行；试验要求两个长例各不少于 600 个有效代码行且不超过 700 个物理行，并记录 LOC 与 token 数。除单文件指标外，检查函数/类型/符号覆盖、跨函数状态与接口、依赖及调用关系、跨段引用、遗漏/重复代码、合并结果和副作用。长文件 Skill 是减少语义漂移的过程性约束，不构成正确性保证。

### 3.4 本轮探索与 RAG 比较

已批准的下一步是**受控探索性试验**：先不使用 RAG 跑通转换流程，不设最低准确率通过门槛但记录逐例基线；再对同一组样例做有 RAG 对比。比较时固定模型、提示主体、Skill 内容、样例、目标环境和生成参数，只改变是否检索并注入知识；可重复次数应两组相同。

当前已归档用户选定的 uhttpd C 源快照（GPL-2.0-or-later，1,317 物理行）作为超限探索候选；C01/C02 可复用它做两个 OS 方向任务，但仍只有一份独立长代码样例。C01 已有 run-01 智能体文本探索稿与 run-02 由 `.env` 配置模型生成的文本探索稿；run-02 随后在用户授权的隔离第三方 VM 上完成了探索性 comparison，并对原始稿做了一轮模型驱动 repair，但不是冻结的 No-RAG 基线。全四例所需的第二独立长源、统一工具链/oracle、隔离配置与逐例批准仍待完成；C03/C04 仍为规格。来源、范围与 oracle 见 [四例矩阵](test/four-case-matrix.md)。

四例仅作为探索性样本，报告逐例差异，不外推为普遍准确率。分别观察：

- 目标语法/编译结果；
- 单文件行为 oracle 的通过、失败、不确定及失败类别；
- 长文件结构/符号/行为覆盖；
- RAG 检索依据的适用性、来源正确性和无关内容；
- token、时延和成本变化。

检索命中率与下游转换行为结果是不同指标。RAG 是否值得长期采用，在试验后依据提升、退化、来源可追溯性与维护/成本共同决定，不预设一定有效。

## 4. 当前真实能力

| 维度 | 当前状态 | 不得宣称 |
|---|---|---|
| 任务模式 | 根入口可区分片段/单文件；长文件工作流初稿已写、未经转换效果验证 | 片段语法率或单文件功能率已达标 |
| 语言方向 | C → C++ 知识初稿 | 其他方向已支持 |
| 语义场景 | 网络 I/O、文件 I/O、并发场景初稿，均未经转换验证；进程等场景尚无 | 已覆盖所有攻防场景或已验证行为 |
| 系统迁移 | POSIX ↔ Winsock 套接字、POSIX ↔ Windows 文件路径/线程初稿，均未经转换验证；进程等系统方向仍无 Skill | 新项目跨 OS 已实现/验收，或任一系统方向已通过转换验证 |
| 长文件 | 计划上限为 700 个物理源代码行；已归档一个 1,317 行 uhttpd 超限候选并生成 C01 文本探索稿，尚无转换验证证据 | 两个 ≥600 LOC 长例已验证或整体 700 行能力已达标 |
| 智能体接入 | Codex 仓库 Skill 显式发现路由已冒烟；本工作区已按 `.env` 配置请求模型生成一份 C01 文本探索稿；其他平台未接入 | Codex 自动触发、其他 Agent 已验收或模型输出已验证 |
| RAG | 尚未实现；已批准设计阶段做对照试验 | 已有检索能力或 RAG 已提高准确率 |

旧仓库中的 640 行 fixture 仍是同平台候选；uhttpd 上游源是用户已选定的超限探索候选，源文件、README 和 GPL 许可证固定保存在 `docs/test/sources/uhttpd/`，但 C01 run-02 已经用户逐例授权后在隔离第三方 VM 完成探索性编译/运行；这不代表其他样例获批。历史跨 OS 报告及自动生成样例仅是候选资料，其证据不继承到本项目。所有试验源文件与转换产物统一放在 `docs/test/`，四例必须先经过来源/许可、安全性、语言方向、系统方向、场景与行为 oracle 筛选。

## 5. ATT&CK、知识来源与安全范围

ATT&CK Enterprise 完整分类是索引，不是覆盖承诺；名称和 ID 以 [MITRE 官方列表](https://attack.mitre.org/tactics/enterprise/) 为准。语言/平台/协议事实优先查标准、官方 API 文档与 RFC；GitHub 用于发现公开案例，需检查版本、许可和上下文，不把 README 或自动生成输出直接当作规范。

试验样例只进入经审阅、获准且与隔离环境匹配的范围。网络类行为使用 loopback stub/mock 或无外联 fixture；不连接真实目标、不使用真实凭证、不通过转换新增攻击能力。动态行为试验若需真实样本或扩大网络/进程副作用，必须另行定义授权和隔离条件。细节以 `docs/安全边界.md` 为准。

## 6. 非目标与启用条件

当前仍不建设独立转换服务或本地构建/评测运行时；闭环由 Markdown Skill 规定确定性门槛、由获批第三方返回权威证据。当前不建设完整 RAG 平台、通用 Registry、固定输出 Schema、hash/升级系统或完整评测平台。最小实验能够回答问题时优先用智能体原生能力和静态文档；出现真实瓶颈后再加薄代码。业务阶段与交付顺序见 `docs/stages/README.md`。
