## 1. 目标与边界

保留 42 方向、7 语言页、4 场景、5 系统及长文件/批次工作流的组合架构。解决规则真源重复、旧口径残留、知识归属与加载条件不一致、产品依赖开发期规格的问题。原有未提交修改保留并在当前文本上演进；不重置工作区。

本包属于工程维护，遵循[开发规范](../../../项目开发规范.md)、[业务边界](../../../项目业务文档和能力边界.md)、[Skill 编写规范](../../../Skill编写规范.md)与[安全边界](../../../../references/framework/safety-boundary.md)。Stage 3 继续管理平台侧事项；本包不改变产品阶段、验收指标或动态执行授权。

## 3. 实施顺序

1. 统一任务、评估准备和交付契约；将正式转换主链写入单项闭环，清除 BLOCKED 文本转换例外。源侧预检先构建，需行为评估时还须在生成前取得冻结条件下的有效源运行基线，不能在架构整理中收紧为一律只构建。片段使用声明上下文预检；明确文本交付不触发后续动态行为评估，但不豁免正式转换的分类/适用源侧预检。
2. 批次新增材料保留同一 batchId，以新增 intake/版本关联追加登记；方向、模型、工具链、oracle 变化另记关联变体，不覆盖原冻结。状态与功能结论分离。
3. 驱动禁令保持：只能消费用户/获批平台已提供的精确驱动或入口；缺失记准备缺口，不让 Agent 或其委托模型代写，不为省事降级可观察库。
4. 交付完整性按模式、实际阶段、停止原因核对：生成后因自审/安全等停止可部分交付；未提交的 job 不要求虚构证据，已发送未知或仍活动的 job 不得收尾。已提交的正常双侧/仅编译项仍要求真实 job 证据。
5. 把普通输出事实移回语言页、方向映射移回对应方向；并发仅保留并发义务，系统页剥离语言方向与样例专用执行限制。跨域安全行为作为共享专题按实际触发加载。
6. 更新入口、参考索引和平台事实路由；将必需授权字段从 Stage 1 规格提取至 Controller 适配，历史材料仍作为依据，不修改旧报告。

## 4. 不在本轮改写的事项

- 原“单次 ≥40 自动化评测、人工逐项触发不算”的业务验收目标仍保留。当前手工串行链路不能据文档修改宣称满足它；产品文档明确目标与现行操作约束的差距。
- 实际 Controller 能力、隔离、工具链和分类器效果不通过静态审阅重新认证；最新部署记录也不替代现场核对。
- 驱动来源不足属于真实准备缺口，不能通过本架构变更扩大执行权限。

纸面走查保持源码事实不变，只改变任务形态：普通输出且无子进程、单线程统一清理、无安全观察入口仅编译、生成后自审阻断、源依赖缺口、批次新增条目。成功信号是规则可被实际路由加载、下一步唯一、适用产物可齐备且不伪造动态证据；失败时回查对应规则归属/契约，不进行样本实验。
