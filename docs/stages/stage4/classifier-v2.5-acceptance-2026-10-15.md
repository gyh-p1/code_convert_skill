# 分类器 v2.5 修订与验收

日期：2026-10-15，北京时间。用户明确确认验收 v2.5。结论：**当前精确稿的分类器维护回归通过，可进入平台接入阶段**；未修改平台受信集合，未发布或部署新平台，1.0.31 仍只信任 v2.4。这不是正式样本或平台准入端到端验收。

## 1. 缺陷与修订

初始分类器 SHA 为 `e81ceab16f237ffe5316e7fe0d5b6f3856ca53339ab35e46873d5f47522a6313`。在独立远端维护目录重跑现有 70 项，复现 8 个失败子项：XML 命名空间/C# 程序集版本等元数据在一个文件、网络消费者在另一文件时，单文件排除造成完整源集合中的地址漏报。两种文件顺序、开启/未开启分类隔离标志均在原有反例内。

修订 `tools/safety_classifier_v2.py`：先完成输入校验与逐文件分析，再依据完整源集合是否检测到网络信号，使用已校验的同一文本重新分析曾作元数据排除的文件；保持源字节哈希，不再读文件。集合与输入顺序无关，不借全局状态在任务间传递。普通文件后缀及非法地址排除继续沿原逻辑，不把所有字符串提升成网络目标。

原三条准入规则与优先级不变：输入错误 → 未隔离公网/hostname → 高置信凭证；其他 review 类仍按原策略准入。未新增网络许可、运行驱动或默认阻断类别，分类隔离标志仍不证明环境真实隔离。

新增两项到现有测试套件：同一分类器处理后续独立任务时不继承前一任务的网络消费者；批量入口正确消费多文件结果并保留分类器、输入清单与源文件的真实 SHA。所有 fixture 仅作为文本分析，没有编译、导入或执行其内容。

`.gitattributes` 对分类器及其测试固定 LF，防止 Windows checkout 改写受信字节。没有增加辅助脚本、分类器版本分支或平台接受列表。
