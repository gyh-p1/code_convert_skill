# 转换 Skill 静态加载与调度走查（2026-10-11）

> 后续状态更新（2026-10-11）：下文记录初始走查时点，不将旧缺口当作当前状态。§2 的“源预检具体请求尚未登记”已补齐：当前平台提供独立 `POST /api/source-preflights`，[当前协议适配 §2](../../../references/adapter/controller/platform-revision-adapter.md#2-独立源侧预检请求)包含 multipart 字段、source-only manifest、完整 InputProfile 1.0 最小形状、metadata、分类/授权要求及手工打包/提交命令，根步骤 1 和发现入口必读可达。平台相关产品路径已纳入本地回归；初始报告未进行真实 VM/job 验收的事实不变。每项合法入口、独立授权、隔离和有效基线仍需实际核对；缺件暂停、禁止先生成目标凑包继续适用。

## 1. 范围与结论

本次按新会话 Agent 的阅读顺序模拟：发现入口 → 必读契约 → 静态画像 → 选择知识 → 冻结 → 单项调度 → 异常/正常收尾，再回查分支入口。审阅对象为当前工作区文本，包含上一轮尚未提交的 frozen-inputs 前置门禁改动。

发现并修正了加载时点、语言页必读口径、调度粒度、知识消费证据及部分 C→C++ 指导的歧义。修改后的入口能给出下一动作、推进依据和停止去向；但本次只能核对文档决策路径，不能证明 Agent 每次都会执行，不能证明自动拦截、现役平台能力或转换效果。

没有实际转换样本，没有调用分类器/配置模型/Controller，没有编译或运行；没有新建模拟任务、虚构冻结哈希、请求、job、result.md 或 PASS。下文的样本特征、成功条件与异常均为假设，供人工推演，不作为转换证据。本报告是一次性工程审阅，不加入产品 Skill 的必读链。

## 3. 模拟一个单项的阅读与调度

假设用户提供一个 C11 长/复杂单文件，要求转 C++17，源 POSIX、目标 Windows；实际画像若发现命令行解析、二进制文件、socket 与 pthread，则按以下路径选择。此处不假定源可构建、分类允许、驱动合法或平台支持；每个结论都要在真实任务中取得依据。

| 时点 | Agent 应读/做什么 | 本步明确产出或条件 | 缺口时处理 |
|---|---|---|---|
| 发现入口 | 读取 .agents/skills/code-convert/SKILL.md，转 AGENTS.md 与根 SKILL.md | 确认是 Markdown 知识 Skill，手工逐项调度，本机只读写文本 | 不从方向页独立生成 |
| 根步骤 1 | 依次读任务状态、安全、交付、分类、构建前提、评估准备、闭环；适用工作流与渠道适配 | 知道身份、模式、落点、预算、平台能力及每个停止分支的报告义务 | 准备缺口记录真实原因，不猜接口 |
| 根步骤 2–3 | 只读源码与材料，定位入口/API/条件分支/输入输出/资源及副作用，再形成标签 | 标签来自源符号和使用点；候选 sourceOs 不是构建结论 | 不按 ATT&CK 标签推断 API，不以头文件印象判源不可构建 |
| 根步骤 4：知识 | 读共性索引、C 与 C++ 两页、c-to-cpp；按实际行为加载场景/系统/安全专题与方向内专页 | 记录符号/范围 → 规则章节/版本 → 适用理由；准备本轮实际正文 | 缺必要语义/版本记具体缺口；不以目录、标题或截断片段充作已读 |
| 根步骤 4：冻结 | 手工写本 run 的 01-frozen/frozen-inputs.md 并回读 | 有实质内容，身份、方向、模式、源集合/哈希及适用组对应；未知与不适用有明确说明 | 不记 FROZEN，不分类；不是等收尾补件 |
| 5.1 分类 | 核冻结门禁，按分类准入手工调用唯一登记分类器，保存真实原文 | 对本项完整源树 ALLOWED，blockingReason=null，身份/版本对应 | 缺件不调用，BLOCKED 不预检/生成/提交，走收尾 |
| 5.2 源预检 | 核真实受支持请求形态、授权/隔离与合法源驱动；在获批环境取证 | 源 build completed/0；行为模式还须有效源基线、终止与清理 | 接口/驱动/隔离缺口先等待；源构建失败真实归因；均不消耗转换调用 |
| 5.3 生成 | 再核冻结与源证据，核模型协议；实际请求包含冻结源范围和适用知识正文 | 完整响应、模型来源、请求/响应/目标版本与用量原件可回读 | 截断/传输按有限重试留原文；不代写目标、不默换模型 |
| 5.4 自审/修订 | 独立审当前稿，逐条看定位与归因；必要修订由配置模型完成 | 有效有限自审且无未解决可定位转换问题可以推进；新稿关联父版本并复审 | 不无限复审；源已有/装置/未知差异不盲修；预算耗尽走适用部分交付 |
| 5.5 准备/提交 | 再核精确版本、分类/授权、安全/隔离、合法驱动四要素、两侧对称、oracle 适用状态 | 所有适用条件通过才保存 attempt 并提交；文本/仅编译分支按契约适用条件走 | 可观察但缺合法驱动不能降级；仅编译支持未知则待准备 |
| 5.6 回执/取证 | 已有 jobId 查询原 job；终态后逐件取回真实证据及清理依据 | job/版本/角色与证据对应；实际适用件齐备 | 无回执但可能接收保持 WAITING/SUBMISSION_UNKNOWN，不盲重投 |
| 5.7 判读/反馈 | 读精确版本两侧原始观察，分编译/链接/启动/行为/安全，先归因 | 只把有定位的转换引入问题交有限修复；新稿取得适用新证据 | 不改平台原 verdict，不从 matched、输出非空或自审推断 PASS |
| 根步骤 6 | 按统一收尾入口写真实 result.md，逐件回读适用产物、版本及指针 | 正常、失败、非可转换及暂停都有报告；缺必备件不得终态 | 未决提交/活动/未确认清理仍 WAITING；报告存在不解除 |

当前文档独立提供的普通双侧请求无法证明 5.2 可操作。真实 Agent 若没有其他已授权且可回读的源预检调用契约，应在准备阶段停止推进；本次后续行仅说明条件满足后的分支，不假装实际走通。

## 4. 知识选择推演

下面只说明假设源码事实触发哪条读取路径；没有真实样本，因此不登记为某转换项“Agent 已读/模型已注入”。

| 假设事实 | 应加载正文 | 应带进生成/审阅的义务 |
|---|---|---|
| C11 → C++17 | 共性索引、languages/c.md、cpp.md、directions/c-to-cpp/SKILL.md | 实参范围、错误、字节/常量、所有权及目标标准限制 |
| getopt/argv 推进 | 两语言参数规则、方向规则 5/6 | 入口计数与消费后范围一起核；冻结 libc、扫描策略和诊断条件 |
| goto cleanup / case 跳转 | C 普通控制流、方向规则 2/9 | 保持出口与释放时机，不因 RAII 或加块改变源控制流 |
| 公共 C 接口/结构体布局 | c-to-cpp/references/type-abi.md | 语言链接不证明布局兼容；内部消歧不能改变公开 ABI |
| 目标 Windows 头与 min/max | c-to-cpp/references/header-macro.md | 原宏求值次数、类型与生命周期；NOMINMAX 的项目影响 |
| 文件字节与跨 OS 路径 | file-io、posix-windows-filesystem、安全行为适用节 | 字节/文本翻译、路径编码/存在性/链接、错误与实际文件证据 |
| socket 跨 POSIX/Windows | network-io、posix-winsock、安全行为适用节 | 部分 I/O、就绪/终止、句柄/错误来源、初始化与对应链接参数 |
| pthread 与共享状态 | concurrency、posix-windows-threads | 生命周期/同步/关闭责任；取消无通用替换，不凭等待宣称无竞态 |
| fork/exec（另一个假设分支） | process-execution、posix-windows-process-identity | 父子分支、映像替换、环境与不可映射点；Windows 启动新进程不能自动视作 fork 等价 |
| C# → Ruby，实际访问注册表/SCM（另一个分支） | C#、Ruby、csharp-to-ruby、windows-registry-service-subsystem；回调/并发另按事实加读 | 同 OS 专有子系统也触发系统页；没有映射/版本事实不能由标题推定覆盖 |
| 长/复杂文件与多项任务 | long-file-conversion；含多项时另读 batch-conversion | 地图/闭合单元与整项有限预算；冻一项就推进一项，不批量冻结 |

仅把上表列入选择清单不能证明模型消费；只有实际发送请求中的适用正文及关联原件支持“模型已注入”。规则效果仍须精确目标版本的独立证据。

## 5. 异常分支推演

各行是单一条件变化下的预期文档决策，未经动态执行。

| 编号 | 改变的条件 | 应阻止/允许的动作与后续去向 |
|---|---|---|
| G01 | 冻结文件不存在 | 不分类/预检/模型请求/新提交；补真实冻结并回读，停止/暂停走报告 |
| G02 | 文件为空、模板占位或属于另一项/run | 与缺文件同样不能放行，不能仅核存在性 |
| G03 | 文件存在但当前动作所需准备件未知 | 存在性不解除准备缺口；停受影响动作 |
| G04 | 恢复发现冻结缺件，但已有活动 job | 停新增动作；继续原 job 查询/取证/终止清理，保持 WAITING |
| G05 | 分类 BLOCKED 或身份/哈希不对应 | 不主观 ALLOWED，不预检/生成/提交；保留原分类并报告 |
| G06 | 仅知道双侧 capsule，无源预检精确契约 | PREPARATION_GAP，不生成目标填包，不自造字段或端点 |
| G07 | 源 build 非零 | 用真实诊断区分不可构建/依赖等，不调用转换，不回填目标 FAIL |
| G08 | 源 build 成功，但服务未就绪/只有 usage | 没有有效源基线，停生成；不能把正常退出或非空输出当行为覆盖 |
| G09 | 预期错误分支退出非零，但观察满足冻结目标 | 不仅凭非零认定基线失败；还核原始观察、终止/清理与适用条件 |
| G10 | 驱动有启动、采集、终止，缺“到达观察状态” | 四要素未齐，不能提交；补合法提供者的精确驱动 |
| G11 | 有安全观察口但缺合法来源入口 | 准备缺口，不由 Agent/配置模型造辅助驱动，不降仅编译 |
| G12 | 真无安全观察口，但现役仅编译支持未知 | 待准备，不发普通运行 job；若停止按已达阶段真实交付 |
| G13 | 明确文本交付或合法无行为片段 | 不强迫后续行为 job，但正式生成仍需冻结、分类与适用源预检 |
| G14 | 只读路径/标题，未读必需正文或实际请求未含正文 | 不声称已加载/注入；补材料，缺必要语义停止受影响请求 |
| G15 | 响应空白/截断 | 留失败原文，有限重试/分块；不是代码 repair，不记生成完成 |
| G16 | 有效 NO-REPAIR-IDENTIFIED，覆盖和记录完整 | 可以推进，不为预测编译结果反复重审 |
| G17 | REPAIR-RECOMMENDED 指向源已有或未定位问题 | 不自动修复；逐条追加裁决，有依据的转换引入问题才修 |
| G18 | 自修/评估后修复预算耗尽且仍有确认问题 | 停止并适用部分交付，不靠分段/新 run 重置累计预算 |
| G19 | POST 超时，无回执，可能已接收 | WAITING/SUBMISSION_UNKNOWN；走已支持恢复渠道，不盲重投 |
| G20 | 平台 matched，但两侧都只执行 usage | 不采信为任务功能一致；报告观察不足，保留平台原判定 |
| G21 | 新稿引用旧稿 PASS | 不能继承；重新关联自审/准备及适用新证据 |
| G22 | 缺 result.md 或实际应有目标/原件/核对记录 | 不 DONE/PARTIAL/CLOSED；交付缺口不能被功能 PASS 抵消 |
| G23 | 有暂停报告，但 job 活动或未确认清理 | 仍 WAITING，不用 PARTIAL 绕过未决执行 |
| G24 | 新增第 40 个唯一 DONE/PARTIAL，或对账缺档 | 增量对账并带遗留，恢复/重提不重计；缺档立即停新增转换 |

## 6. 回查范围与未验证部分

先穷举磁盘，再人工核对加载提示与本次新增链接：当前有 54 个 skills/**/SKILL.md（42 方向、4 场景、5 系统、战术索引、2 工作流），另有发现入口、根入口、AGENTS.md，共 57 个加载/协作入口；共享参考 9 页、方向内专题实际发现 2 页。计数描述本次磁盘，不当未来固定清单。

逐个核对全部 42 个方向的根回链、源/目标语言路径及名称；全部 9 个场景/系统的前置加载提示；战术与两工作流的回根关系；7 语言页必读提示及共性/安全参考的适用边界。新增相对路径按所在目录与磁盘对应，新增锚点按实际标题人工核对。链接核对针对正文中明确的 Markdown 引用，不把代码中的强制转换或 lambda 记作链接。

主干回查覆盖发现入口、AGENTS、根六步与调度表、任务状态、评估准备、闭环、分类、构建、交付、安全和 Controller 适配；检查冻结顺序、语言加载时点、源预检、准备缺口、仅编译、自审有限推进、未知提交、终态及批次对账口径。新增规则分别通过入口提示或真源引用可达，没有要求 Agent 加载工程报告。

知识正文重点抽查 C/C++、c-to-cpp 及其专题，以及场景/系统的触发、限制和门禁措辞；不是 42 个方向所有技术事实的全面复核，也不是七语言全矩阵转换验证。工具输出若截断，未显示范围不能据此记为某任务已经读取。

未验证：配置模型实际协议/调用工具、源预检现役请求契约、仅编译能力部署、分类器当前实例、逐例 VM 隔离、真实编译/运行/比较、自审和修复实际效果，以及 Agent 在长会话中遵守手工门禁的可靠性。源预检缺口的下一项准备材料是平台合法请求示例和精确契约，不是本仓库新增运行器。

本次使用原生文件读取、rg 穷举/检索及人工 diff 审阅；git diff --check 未报告格式错误。未编写或执行扫描/链接检查脚本，未把这项格式检查称为语法、构建或行为测试。

本次改动保留前置冻结核对及收尾完整性核对。它们分别回答“当前是否能继续”和“当前是否能收尾”；收尾检查无法替代提前阻止漏冻结的作用。本地文档修改也不能证明已经运行的旧会话重新加载了这些规则。
