# 消噪、功能分类与统计口径审查提案

> 回应用户：认可扩大有语义依据的消噪，认可把有效matched与有效semantic_pass合计为“冻结范围内比较通过”。本稿是优化方案，未改平台配置、规则真源、历史证据或状态。
> 本稿基于当前比较适配、evaluation-core源码及已读历史原件，不宣称277项全目录已审完；逐项范围见[索引](full-review-index-2026-10-12.md)。

## 1. 顺序

建议流程为：**确认观察有效 → 保留原件并按冻结规则消噪/映射 → 比较及差异归因 → 功能一致性分类 → 按唯一用例及最终版本分层统计**。

观察有效是比较前提，不能先将两侧空流、驱动自身输出或未到达被观察路径的材料消成“相同”。有效的错误/拒绝路径可以作为该路径的比较证据，不能因它不是成功路径就一律排除；同时不能外推成功分支已覆盖。

语法写法差异本身不是观察噪声。跨语言语法通常差别很大，评估应看同一义务对应的结果、状态和副作用。系统差异适合通过明确映射表达，例如平台错误类别、路径根、环境身份；不需要要求所有字符串都逐字相同。

## 2. 扩大消噪的具体范围

| 差异类别 | 可采用的宽泛处理 | 必须保留的语义/前提 |
|---|---|---|
| 行终止符/编码/JSON键顺序 | 合同允许时按逻辑文本/结构解析；区分BOM和展示形式 | 二进制/协议/文件字节义务不能同样归一；null、布尔、数值、字段存在性不混淆 |
| 驱动封装 | 按已提供驱动精确协议提取程序stdout/stderr/退出 | 保留原封装，证明真实启动/到达/采集；不能猜任意字符串皆JSON，不能拿驱动exit=0代程序exit |
| 临时目录/工作区前缀 | 将两侧已确认根映射到同一逻辑根 | 相对尾路径、父子关系、路径逃逸、实际副作用对象须保留；不要替换全部路径为一个符号 |
| 时间/PID/动态端口/随机名 | 展示值按类型/身份关系规范化，保持多次引用一致 | 截止时间、duration单位、顺序、成功连接对应端点、checksum及源固定端口受保护 |
| 目录/集合次序 | 源不承诺顺序且消费者不依赖时按集合/多重集合比較 | 数量、重复项、缺失/额外项受保护；数组不是天然集合，稳定排序义务另核 |
| 运行时异常/栈/本地化文案 | 按源冻结失败类别比较，允许诊断外形/栈不同 | 错误触发、传播、退出、部分结果、stdout/stderr通道和继续/终止仍保持；不是全stderr ignore |
| 主机/用户/进程/服务状态 | 对冻结环境身份或只读动态状态建立对应关系与允许窗口 | 不把ACL、管理员判定、可访问性、漏映射状态都消为环境；保留稳定字段/成员集/分类结果 |
| 构建/装置文件 | 用阶段基线/提供者来源识别与业务副作用分列 | 不全局忽略exe或pyc扩展名；业务可能生成这些文件，目标新增越界副作用仍需发现 |
| ZIP/gzip字节/时间戳 | 源未要求压缩字节相同时，比较解压成员、内容、清单与格式合法性 | CRC/读取到EOF、重复/额外成员、算法支持范围与错误传播；不能只比archive大小或共同编解码自洽 |

当前平台部分仅支持整个流的normalized-text、JSON ignored paths、文件模式及v2根映射。逐字段语义映射、可靠驱动协议解析、事件oracle等**不能伪造为现有功能**；不能在capsule偷偷塞未支持字段。

消噪结果应保留原始差异、规则及版本、命中位置、允许依据和保护义务。策略不适用时原判仍保留，另记策略问题；需要更广策略时另冻变体/配置，由平台重评。禁止结果出来后仅为了通过而删除关键字段。

## 3. matched与semantic_pass如何计通过

当前`evidence_comparator.derive_behavior_verdict`中：全部适用维度已观察且matched，得到matched；全部已观察且只含matched/semantic-match、至少一个semantic-match，得到semantic_pass。二者是**比较通过的不同类型**，可以合计。semantic_pass没有天然更差的功能等级，也不是可以接受任意差异。

建议统计展示：

| 功能比较分类 | 是否进入冻结范围通过小计 | 报告方式 |
|---|---|---|
| 有效matched | 是 | 精确/结构比较通过，保留具体模式（matched不总等于全字节精确） |
| 有效semantic_pass | 是 | 允许差异/消噪后通过，列规则与边界 |
| 比较标签通过，但观察/策略不适用 | 否 | 原标签照录；项目结论UNVERIFIED/策略疑点，待平台处理 |
| 有效mismatched且转换归因有定位依据 | 否 | 冻结范围存在转换差异；代码失败与装置失败分别报 |
| mismatched但源已有/环境/装置/归因未定 | 否 | 原判保留；不计转换缺陷，不由Agent改成PASS |
| partial/inconclusive/未采/仅编译 | 否 | 具体缺口，不以0个diff表示通过 |

“有效”核精确版本/输入/配置、适用观察和安全/清理，以及关键义务没有被规则吞掉；**不是要求每个matched都有完整功能覆盖**。例如D2-001 missing_bundle、D2-004 missing文件是有效的局部比较通过，发送/读取分支仍未验证。已修订目标同样只能按其实际评估范围统计。

通过小计 = 有效matched项数 + 有效semantic_pass项数。仍单列两类数量、分母、未决项及未覆盖义务；一个taskId重提/修订不重复计项，不挑最好attempt代最终交付版。不把仅编译项塞入行为分母，不合成交付/编译/功能的单一转换成功率。

若功能比较通过率需要展示，分母可以用**有效且结论明确的功能比较用例**（通过+mismatched），旁列其占全部适用行为项的数量/覆盖；否则排除无证据项会造成选择偏差。全批适用项、实际可判项和仅编译项的集合须展开对账；在全量核完前不发布本数据集的百分比。

## 4. 当前系统还须改的表达与能力

1. 当前比较适配§5/§6写“semantic_pass不直接记功能验收通过”。这应保留“不能仅凭标签代所有验收”的边界，但可明确加上**与matched共同进入有前提、有限范围的比较通过小计**。避免让读者误解为semantic_pass一律不算通过。若改规则须按AGENTS加载路径穷举回查，本轮只记录提案。
2. 当前report_builder的matchedDimensions只计status=matched；semantic-match属于充分观察，但没有单独semantic计数字段，表头数量可能不闭合。建议单列semanticMatchedDimensions或明确通过维度数，并保留旧字段语义，不能直接改历史matchedDimensions数。
3. 当前functional_assessment允许output为matched或semantic-match并满足正向断言时PASS，说明合计思路在有限output断言中已有实现；它目前不提供一般filesystem/network/registry事件级oracle。不能将该PASS泛化为全功能证明。
4. 所有报告应分别展示维度覆盖、路径/义务覆盖、采集来源与剩余语义差异。100% observed dimensions不等于100%功能；程序输出provenance仍UNVERIFIED时不能只看平台closure终态。
5. 修正digest生产者口径与适配说明的冲突：evidence_builder对CRLF归一再算digest，VM bounded_capture算原始字节并覆盖stream digest。exact比较用digest时必须明确原字节/规范化字节含义；这影响噪声与真正字节义务，不能靠统计合并解决。

此方案允许更广跨语言/系统差异，保留业务语义约束。后续全量审阅为每种消噪补具体支持项/反例/平台能力缺口；未审用例不自动套用已审项的归因。
