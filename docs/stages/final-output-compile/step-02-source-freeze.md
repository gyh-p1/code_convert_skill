# step-02：选定并冻结第二份独立 C 源

> 状态：已完成（fe 源快照已冻结并用于 step-03；原四例样本配额随后取消）
> 类型：样例选定与冻结（本步只做只读检索与冻结记录，不编译不执行）
> 归属阶段：[最终交付编译质量与 Skill 拓展](index.md)

## 目标

找 / 确认一份 ~600–900 物理行、许可清晰、可独立构建的独立 C 单文件，冻结源快照 + 目标工具链/标准 + 隔离条件，为后续 comparison capsule 双侧 build 做准备。实际选定 [rxi/fe](../../test/sources/fe/source.md)，作为独立编译质量样源；当时还参考了后来[取消的四例样本计划](../four-case-cancellation.md)，但 fe 不承担当前四例配额。

## 纳入范围

- **只读候选检索**：列出候选，每条给出来源/许可、物理行/有效 LOC、可观察行为、静态安全边界、是否需真实外联。
- 允许攻击性行为的 C 源（VM + 快照兜底运行安全），但要能把网络固定到 loopback/实验网。
- 用户拍板后再冻结：源快照按现有 `sources/` 布局归档 + `source.md`（来源、commit、许可）。

## 非目标

- 本步不跑编译/执行，不下载即运行。
- 不复用 uhttpd 充第二份独立源。
- 不因凑行数而放宽逻辑密度或纳入许可不明的源。

## 依赖与前置

- 与 step-01 无强依赖，可并行。
- 冻结前需确认：隔离 VM + 逐例执行授权范围（跑双侧属运行代码）。

## 预计改动文件

- 实际落点：[fe 源快照](../../test/sources/fe/source.md)与[fe case](../../test/dataset/c-to-cpp/fe-lisp-c-to-cpp/case.md)；旧四例矩阵已在取消时移除。

## 验收依据（人工检查）

- 候选表每条可判定：许可、物理行/有效 LOC、可观察行为、静态安全边界、外联需求都有结论。
- 冻结项齐全：源哈希/快照、源 OS/ABI、目标编译器/SDK/标准、隔离与授权范围、双侧 build 命令。
- 符合安全边界与许可合规（GPL 等随附许可与来源）。

## 风险与停止条件

- 找不到同时满足“许可清晰 + 独立 + ~600–900 行 + 可 loopback 化”的源 → 回报，不硬凑。
- 涉及真实外部目标 / 真实凭证 / 无法 loopback 化的外联 → 排除。
- 许可或来源不明 → 不纳入。
