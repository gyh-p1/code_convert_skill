## 目标

针对 step-07 旧副本来源/改写不清的缺口，从发布方仓库寻找许可证、提交和源文件身份可固定的 C 场景。优先保留真实系统调用与可观察行为，同时明确它与完整真实攻击链的距离。为下一次转换/功能判据步骤选一份**候选**，不把搜索结果直接升级为已批准 run。

## 纳入与非目标

- 只读核对上游仓库、固定提交、许可证、相关 C 源和伴随依赖；对照至少一个不适宜当前边界的候选，记录取舍。
- 静态审阅用户已确认的网络来源；可将上游代码检出到系统临时目录用于只读盘点，结束后清理该临时副本。
- 不把源码复制到本项目 `sources/`，不调用配置模型，不编译/运行任何样本或构建脚本，不提交 Controller job，不修改 Controller/Agent。
- 选中候选只说明下一步值得设计的场景与缺口，不宣称 C→C++、跨 OS 或功能保持已验证。

## 依赖与前置

1. [step-07 审阅](step-07-real-scenario-source-screen.md)已排除三个旧副本的直接准入。
2. 当前质量阶段仍以最终目标 build 为判据；功能检测标准先按具体场景冻结。Windows/Linux same-runner 缺陷与 network Collector 缺口记录为取证限制。
3. 不用公网示例配置或真实目标；候选进入试验前另审隔离 loopback 输入、工具链和清理契约。

- 至少一份真实对抗行为/模拟行为的上游 C 源有固定提交、许可证、源文件哈希/行数、依赖和安全边界；区分“真实系统行为”与“完整在野攻击链”。

## 风险与停止条件

- 仓库有许可但选定文件或伴随资产缺授权/版本，或源依赖无法冻结：只列候选，不导入。
