# 阶段 01：C → C++ 内容与任务模式

> 状态：当前  
> 性质：知识与工作流建设，不是转换效果验收

## 目标

为两种交付模式建立不同的提示与检查边界：片段以语法正确为目标，单文件以语法和可观察功能为目标；长单文件在单文件之上增加结构化处理，计划支持上限为 700 个 LF 归一化物理源代码行。上限不是运行性能通过线，性能指标另行定义。

## 长单文件辅助工作流

长文件不得直接按固定行数盲切。工作流 Skill 应指导智能体：

1. 先建立文件地图：入口、宏、类型、全局/静态状态、函数清单、调用关系、外部依赖、资源和平台 API；
2. 标记可观察行为：输入输出、协议/字节、错误、超时、文件、进程、权限和清理路径；
3. 按完整函数或语义单元制定分段计划，保留共享符号表和跨段引用；
4. 逐段转换时只修改负责单元，不能重复定义或擅自重写外部依赖；
5. 合并后做全文件结构检查：入口、函数/类型覆盖、声明定义、调用关系、全局状态、错误路径、平台条件和重复/遗漏；
6. 输出时区分语法结果、行为依据、未覆盖项和未验证项。

工作流以独立的 [long-file-conversion Skill](../../skills/workflows/long-file-conversion/SKILL.md) 承载；方向 Skill 负责链接，不复制通用流程。工作流初稿已建立，后续只依据人工审阅或受控试验中观察到的问题修订，不直接复制旧运行时的 long-code chain。

## C → C++ 内容顺序

1. 类型、整数转换、布局与 C ABI：已有初稿；
2. 网络 I/O 场景：已有初稿；
3. 进程与错误路径：参数边界、返回码、`errno`、清理与异常边界；
4. 所有权与资源：分配配对、缓冲区、文件/句柄、生命周期；
5. 宏、回调与平台 API：求值次数、调用约定和不可直接映射处；
6. 片段与单文件的输出说明模板，以及长文件结构清点条目。
