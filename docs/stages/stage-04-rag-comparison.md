# 阶段 04：RAG 配对对照

> 状态：待启动（有条件批准的探索性比较）  
> 前置：阶段 03 基线完整、四例和评分表冻结

## 实验变量

RAG 组在相同基础提示和 Skill 上增加经过审阅、带来源的检索片段；控制组不检索。两组固定样例、模型标识、参数、核心提示、Skill 内容、目标 OS/架构、工具条件及行为 oracle，**只改变是否检索/注入知识**。如更新知识内容或提示，应另起实验版本，不能与 RAG 效果混为一谈。

## 分层记录

- **检索层**：每例相关依据的 Recall@k/Precision@k（若有人工标注），来源和版本是否匹配、误引/过期内容、注入 token；
- **转换层**：语法/编译、逐项行为 oracle、长文件结构完整性；按相同口径对照无 RAG 基线；
- **成本层**：检索延迟、额外 token、总耗时/成本；
- **稳定性**：若重复运行，次数与参数两组一致，展示逐次结果和方差，不挑最好结果。

## 结论规则

四例仅是试点，结论限定于这四例和当前知识范围。报告每例改善、退化和无变化；区分“检索命中改善”和“输出行为改善”。若检索指标提高但转换结果无提升，不能据此宣称 RAG 提高转换准确率。明显错误来源、质量退化或安全问题应阻止采用；结果不确定时先改进知识/问题集，再作决定。

本阶段不要求上线 RAG、不绑定向量数据库/供应商，也不构建完整检索服务。试验执行遵守 `docs/安全边界.md`。
