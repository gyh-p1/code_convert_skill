# 必读契约与适用工作流载入核对方案

> 状态：三职责工具已实现，范围内回归与 Codex 宿主文档验收完成；证据及未覆盖事项见[验收记录](../reviews/loading-tool-acceptance-2026-10-15.md)。
> 决策更新：2026-10-15，用户采用三职责小工具，进一步明确仅转换系统本身允许使用已登记脚本；第三方智能体加载 Skill 后仍不得使用辅助脚本，手工逐项调度。
> 本页为实施与验收基准；实际实现、宿主接入及验证范围以验收记录为准，不据计划宣称已验证。

## 1. 目标与边界

当前[根入口必读表](../../../../SKILL.md#必经执行链与契约)规定了 7 份真源及消费时点，但任务记录尚不能统一核验本项需要哪些文件、哪个版本的正文通过工具提供过、是否覆盖完整，以及是否在要求的动作之前提供。

采用一个小工具承担三项职责：检查仓库结构、记录正文提供情况、核对下一动作前置条件。机械检查与留证由脚本完成，适用性判断、规则冲突审阅和行动决策仍由 Agent 按既有契约承担。不另建任务状态机，不把检查结果当作分类、源预检、评估就绪或交付完整性结论。

首版范围仍为发现入口、`AGENTS.md`、根入口、7 份必读契约及批量/长单文件两个条件工作流。语言、方向、场景、系统和 Controller 渠道材料仍须按根入口加载，但本版不证明其载入完整性；输出须明示这个未覆盖范围。后续可沿用同一机制核本项实际选择的知识和渠道材料，不要求每项加载全库。

仅转换系统维护侧可执行已登记加载脚本及文本回归，第三方智能体不编写、生成、保存或运行辅助脚本，只以原生工具读取/核对/引用系统产物，手工串行逐项调度；无系统支持时手工核同范围并注明证据限制。该边界须同步执行真源。本工具只处理文档、任务适用性记录和读取/动作证据，不运行样本、目标或构建，不调用转换模型，不提交评估，不访问 Controller 安装目录及其 `jobs/`。样本编译、运行和隔离要求仍按[安全边界](../../../../references/framework/safety-boundary.md)独立核对。

## 2. 唯一清单与适用集合

7 份必读契约以根 `SKILL.md` 的“必读真源”表为唯一加载清单：任务状态、分类准入、构建前提、单项闭环、评估准备、交付、安全边界。在该表添加稳定契约标识，解析器消费同一表；程序内固定精确身份作为验收约束，以检出同数量替换，不作为另一个加载入口。合法变更需连同约束和验收预期审阅。无法解析表形制或标识重复时明确失败，不退回旧清单报告通过。

条件工作流适用性由 Agent 根据任务事实填写，工具校验依据是否存在及集合是否一致：多项请求在首项处理前加载批量工作流；长或复杂单文件在建图/分段前加载长文件工作流；两者可以同时适用。未知不能默认为不适用；start 时可明确 long-file 待画像确定，map/freeze 及后续动作前须定案。单项闭环已属于 7 份契约，不重复计数。复杂度由源码画像判断，不由工具凭文件名或单一行数阈值猜测。

发现入口与 `AGENTS.md` 可靠导向根入口即可；不要求所有页面直接链接全部真源，不把 `docs/stages/` 加入产品必读链。

## 3. 一个工具的三项职责

### 3.1 检查仓库结构

用 Markdown 解析器检查根表身份、路径、范围内目标锚点与入口路由；明确支持的 Markdown 方言、标题锚点规则及重复标题处理。围栏和行内代码中的链接样例不当成真实链接。范围外目标不递归扩展为加载义务，并在报告中说明跳过的检查。

输出每项 finding、严重度、输入文件 SHA-256、检查器版本/摘要、解析规则版本及检查范围。结构结果为 `PASS`、`FAIL` 或 `UNAVAILABLE`；解析/读取错误不能通过。字节摘要对应实际工作树或选定快照，Git commit 仅辅助定位。

程序检查可明确解析的结构关系，不用关键词出现顺序证明自然语言门禁语义一致。触发描述、反例和规则冲突由人工回查，结论与结构检查分列，不以全库废弃词黑名单替代。

### 3.2 记录正文提供情况

从实际读取调用或可关联的宿主工具日志取得证据，不通过后台扫描生成“Agent 已读”。记录至少包含：文档身份、原字节 SHA-256、正文快照指针、编码/显示转换、实际返回范围、调用标识、Agent/会话身份、可得的上下文恢复标识、时间及有序事件依据、截断状态和原始证据指针。

分段读取以同一正文快照为基准计算范围并集；区间重叠不重复计覆盖，缺中段、混用版本或未知截断状态均不能记完整。显示行号与原字节区间分别标明，换行转换不混淆摘要对象。工具返回与完整快照均须可回读；只有文件哈希、stdout 文件或返回字数不能证明正文已提供给 Agent。

| 依据 | 支持的结论 | 不支持的结论 |
|---|---|---|
| 静态扫描或生成正文包 | 文件存在、材料已准备 | 正文已提供给 Agent |
| Agent 自填读取声明 | 留有读取声明 | 独立确认实际提供或未截断 |
| 可关联实际读取返回、范围与截断信息的工具证据 | 指定会话曾获得这些范围的正文 | 理解、当前仍保有上下文、已注入转换模型、效果已验证 |

实施前先验证宿主能提供哪些真实日志字段。工具本身读完文件，不代表宿主展示没有再次截断；缺少最终提供范围的可靠依据时降级为未证实，不自造调用标识或成功回执。首版不承诺适配任意 Agent 宿主。

同一连续上下文内，正文快照相同且原始读取依据可回读时，批次后续项可引用共同记录，每项仍确认适用集合。换 Agent、换会话或发生已知上下文压缩/恢复时重新提供所需正文并追加记录；摘要和旧凭证本身不证明当前上下文已加载。宿主不暴露上下文事件时，工具必须报告此限制，不能宣称自动检测所有上下文失效。

### 3.3 核对下一动作前置条件

读取既有冻结、适用性说明、阶段/动作记录及上述证据，核适用集合、版本、覆盖范围和读取时序，输出下一动作的具体缺项；不写 `phase`、`lifecycle` 或自动触发下一动作。结果只表示本工具覆盖的加载条件，不能概括全部转换前置条件。

| 核对时点 | 加载核对内容 |
|---|---|
| 加载完成、开始处理本项前 | 7 份契约及本项对应版本的正文提供依据；允许先完成读取和记录准备，再核对开始动作 |
| 批量首项处理前 | 批量工作流及触发事实 |
| 长文件建图/分段前 | 长文件工作流及触发事实；不得等冻结时才补读 |
| 冻结完成前 | 汇总适用集合、静态报告、读取覆盖与时序；结合既有冻结落盘/回读门禁 |
| 后续正式动作或恢复新增动作前 | 核本次引用仍适用；按既有契约复核应消费的规则及版本 |

时序优先引用同一可信日志的事件顺序或因果关联，时间戳仅辅助；跨来源无法比较时记未证实。事后补读不能追认历史动作合规；保留缺口，完成当前补读并按既有契约核受影响产物与恢复条件，再决定后续动作。不得删除真实阶段或伪称此前未执行。

人工回退必须保留同范围检查依据，并明确 `manual` 来源；不能通过填模板覆盖工具 `FAIL`，也不能把没有工具日志的声明提升为独立提供证据。输入缺失记 `UNAVAILABLE`，已知缺项记 `FAIL`；符合本层范围才可 `PASS`。

检查工具可被绕过时，这仍是 Agent 流程核对。只有检查已接入实际动作入口、替代路径也被覆盖且经过绕过测试，才能宣称相应范围的技术拦截；首版不扩建通用调度系统或 Controller 门禁。

## 4. 版本、产物与失败去向

读取证据绑定实际正文快照，静态报告绑定同一输入集合的版本。运行期间工作树变化不修改旧凭证：已有 run 是否继续使用原快照、是否切换规则创建变体，按[任务状态 §2.1](../../../../references/framework/task-state-contract.md#21-版本关联与复用边界)处理；找不到旧正文记缺口，不能用新文件哈希刷新旧读取记录。结构与读取结果版本不符不得互相代用。

允许工具直接写入约定的证据目录：单项放本 run 的 `01-frozen/`，批次共享原件放既有批次级记录位置。采用唯一身份、原子写入及禁止覆盖旧原件；写入失败不能返回成功。`frozen-inputs.md` 和既有阶段记录仅保存适用性、原件指针及核对结论，不另建逐项状态台账。原始日志保留，派生报告注明来源和工具版本。

冻结前不满足适用加载条件时不新记 `FROZEN`，不新增分类及后续动作；后续发现缺口则停止受影响的新动作。所有停止/暂停仍走[交付 §1.1](../../../../references/framework/delivery-handoff-contract.md#11-统一收尾入口与报告义务)，报告已达阶段、缺口和恢复条件。已发生 job 的查询、取证、终止和清理不受此缺口阻断，不另造 job 或改写平台结论。

本工具证据成为本项适用产物时，由既有交付完整性核对消费；文件存在不等于内容有效。工具输出分别保留结构结果、正文提供证据等级和下一动作的加载核对结果，不合成“转换通过”。

## 5. 最小实现与接入顺序

建议保留一个入口 `tools/loading_preflight.py`，提供 `check-repo`、`record-read`、`check-next` 三个子命令；参数形状在宿主证据接口核实后定稿。`record-read` 消费真实读取证据，不接受仅由调用者填写的 `complete=true` 作为完整依据。共用退出码：`0` 表示本次声明范围的检查/记录操作成功，`1` 为已知缺项，`2` 为用法、读取、解析或能力不可用；记录操作成功不表示加载门禁通过。

1. 同步角色与产品执行真源：`AGENTS.md`、根/发现入口、安全边界、任务状态、交付、相关工作流及开发规范。明确仅系统可执行登记组件，第三方智能体继续禁止辅助脚本并逐项调度，保留样本执行、隔离与真实证据边界；不为已明确的系统维护授权再次询问。
2. 先做宿主读取证据最小实验，核实际返回、截断和会话标识的可获得性，确定强证据与降级边界。证据能力不足时允许先交付结构检查，正文记录/下一动作核对如实标部分实现，不能用合成日志冒充接入成功。
3. 实现解析、分段覆盖及前置核对，共用正文身份和原件指针；不引入模型调用、转换循环或新任务状态机。
4. 接入既有消费时点、冻结与交付记录；测试失败/暂停、历史 job 例外、批次复用和正文变更。验收报告列明哪些只是 fixture、哪些实际连通宿主。

## 6. 验收与效果验证

先用文本 fixture 做单变量实验，每项记录输入版本、原始输出、预期与实际、退出码。四种任务形态覆盖单项、批量、长文件、批量且长文件。

| 单一改变 | 预期信号 |
|---|---|
| 删除一份必读项；或保持 7 项但替换一个身份 | 结构检查分别检出缺项/错项 |
| 损坏范围内锚点；或使根表不可解析 | 对应检查失败，不能回退旧清单通过 |
| 仅在代码块/历史引述出现反例词 | 不因词语出现误报现行规则冲突 |
| 分段遗漏中段；或最终工具返回截断 | 正文覆盖不完整，即使后台读完也不通过 |
| 读取后改变正文；或混合两版分段 | 新版不能继承旧版完整覆盖；旧原件保留 |
| 先建图后读长文件工作流 | 报历史时序缺口，补读不追认此前合规 |
| 换会话或模拟上下文恢复，仅携带旧凭证 | 不自动判当前上下文已加载，要求补充提供依据 |
| 缺少宿主返回日志，仅有自填声明 | 显式降级；独立提供证据仍未证实 |
| 重复输出身份或写入中断 | 旧原件不被覆盖，不报告保存成功 |
| 缺加载凭证但已有活动 job | 阻断受影响的新动作，允许既有查询/取证/终止/清理 |

再在无需执行样本的真实 Agent 文档任务中核工具返回、快照和报告的一致性，收集误报、漏报、补读次数及额外耗时。以相同文档任务比较原人工记录和新工具流程，单独改变记录/检查方式，报告样本量和限制；fixture 通过不代替实际宿主接入或使用效果。

各部分按实际证据记录实施与验证状态，未实现或未验证部分分别记 `NOT_IMPLEMENTED` / `UNVERIFIED`；任何结构/读取验收均不证明转换、编译、行为、隔离、模型注入或不可绕过的技术门禁。当前实现和宿主验收见上方验收记录，不据此宣称全库回归全绿。
