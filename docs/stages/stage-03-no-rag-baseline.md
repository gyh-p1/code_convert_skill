# 阶段 03：无 RAG 全流程基线

> 状态：待启动（已批准的探索性试验）  
> 前置：阶段 02 的四例材料、安全审阅、oracle 与隔离方案全部就绪

## 目标

用人工选择/显式加载的现有 Skill 和基础提示跑通四例转换流程，不使用 RAG，不设置准确率通过门槛；按 `references/conversion-evaluation-loop.md` 固定自审、自修预算、评估前置条件、第三方结果分流和有限 repair 规则，完整记录每例数据，形成阶段 04 的冻结基线。源代码和各组目标文件/结果说明均保存在 `docs/test/cases/<case-id>/`，按 `source/`、`output/no-rag/`、`output/rag/` 区分。流程跑通不等于目标正确。

## 固定与记录

- 固定四个源文件的路径/名称与只读副本、源与目标 OS、语言、场景、ATT&CK 元数据、行数与 token 数；
- 记录基础提示、Skill 内容、模型标识/可用快照、参数、上下文、工具环境与目标环境，作为本次实验条件；不引入 Skill hash 或项目版本升级机制；
- 明确哪些检查为语法/编译检查，哪些为受控行为检查，哪些未运行；
- 如模型存在随机性，基线与后续 RAG 组采用相同重复次数/参数，并保存每次结果，不只保留最好一次。

## 每例指标

1. 语法/编译：通过、失败、无法判定及诊断；
2. 行为 oracle：逐项通过、失败、不确定、未覆盖；
3. 长文件完整性：入口、函数/类型/符号覆盖、跨段引用、状态/错误/副作用核对；
4. 流程：是否完整产出、是否截断、人工干预点、自审发现率、自修/外部 repair 次数及停止原因；
5. 成本：token、耗时和可得的成本数据。

本阶段不设合格分数，只记录原始结果、失败类型和流程阻塞。遇到未获审阅样例、超出安全边界的能力或隔离条件不满足时立即停止该例，不因跑完四例而绕过门槛。
