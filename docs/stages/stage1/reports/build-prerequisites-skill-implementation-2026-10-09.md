## 1. 全量盘点结果（动手前）

对 `skills/` 下 **54 份 `SKILL.md`** 逐份检索构建相关关键词
（`ws2_32`、`编译命令`、`构建命令`、`链接库`、`.csproj`、`GOTOOLCHAIN`、`GOCACHE`、`go.mod`、`构建前提`）：

| 结果 | 数量 |
|---|---:|
| 有构建前提内容的文件 | **1**（`systems/posix-winsock/SKILL.md` 第 43 行表格单元格） |
| 无任何构建前提内容 | **53** |

其余 3 处"命中"经人工核对为**误报**：`go-to-csharp` 的 `CreateLinkedTokenSource`、
`network-io` 的 `link_local`、`posix-windows-filesystem` 的 `symlink_status`
都只是碰巧含 `link` 子串。

**结论**：42 个语言方向 Skill **全部没有**构建前提规则。
`posix-winsock` 虽提到 `ws2_32.lib`，但只是映射表里的一格，**不是可执行规则**，
也未说明"该写进契约"。

## 2. 结构盘点（决定插入位置）

42 份方向 Skill 存在两种结构：

| 组 | 数量 | 尾部章节 |
|---|---:|---|
| A | 36 | `## 转换与验证边界` |
| B | 6 | `## 四、跨场景与系统规则按需加载` / `## 四、按需加载的专题与场景规则` |

B 组为：`c-to-cpp`、`cpp-to-c`、`c-to-go`、`c-to-python`、`go-to-c`、`python-to-go`。

**设计选择**：不把完整规则复制进 42 份文件（会造成 42 处重复且易漂移），
而是**新建一份共享参考页 + 42 处一行指针**。

## 3. 实际改动

### 3.1 新建：`references/workflow/build-prerequisites.md`

共享规则页，含 7 节：

| 节 | 内容 |
|---|---|
| §0 | 为什么需要（四项真实构建失败的对照表） |
| §1 | **核心原则**：构建前提必须写进契约；依据是 Agent 直接取 `manifest.buildCommand` |
| §2 | 按目标语言的前提：C/C++→Windows（Winsock 链接、头文件顺序）、→C#（工程文件、目标框架、引用、unsafe）、→Go（工具链版本、缓存、`go.mod`、cgo）、→解释型语言（版本、依赖、语法入口） |
| §3 | **C# `.csproj` 补齐的三个硬性要求**：最小中性、**同时记录原本缺什么**、随源码移交 |
| §4 | 工具链版本（显式处理、禁止静默降级）与构建缓存/HOME |
| §5 | 何时把责任判给环境（归因对照表） |
| §6 | 与其它文档的关系 |
| §7 | 证据边界 |

**§3 第 2 条是本文件的关键防线**：总评估报告 §6#3 自己指出"补 `.csproj` 会掩盖真实缺失类型"，
因此规则强制要求记录"原本缺什么"，防止把源依赖缺口伪装成环境已修好。
