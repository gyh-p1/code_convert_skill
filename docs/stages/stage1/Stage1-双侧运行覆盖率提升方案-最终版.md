## 1. 目标与明确边界

交付一个可开发、可逐项验收的工作包：优化分类分流，修复 batch-01～06 暴露的问题，恢复双侧取证，
形成并部署最新第三方评估平台，验收后把完整系统剥离到 `E:\桌面文档\Agents System\third-party-evaluation-system`，
交付后**等待用户批准**再开始转换测试。

本轮用户已明确允许修订/重跑静态分类器；实际只在本机运行该文本分析工具及合成回归，未导入、编译或执行任何样本。
这是指定工具操作的范围，不扩大为本机运行转换产物、Controller、Agent、构建或部署脚本的许可。

T06–T08 取消：不开发分类器 HTTP 服务、新 Agent 调度封装、Docker 镜像。不以新工具框架替代现有 Controller 路线。
平台优化在候选评估仓库实施，当前转换仓库保持 Markdown Skill 与消费适配边界。转换业务阶段、42 方向、≥10 战术、
三类 OS、≥600 行和≥40 项自动批次的交付基线不因本文自动验收；见[业务真源](../../项目业务文档和能力边界.md)和[开发规范](../../项目开发规范.md)。

## 4. 分类器与准入：本轮完成内容

分类器仍是轻量、只读的启发式工具，不是多语言编译器或完备行为分析器。保留文件名与 SafetyClassifierV2 入口，内部版本升为 2.3：

- 注释与字符串按基本词法分离；未知语法、编码、扩展名保留不确定，不静默忽略。
- 地址字面量不因赋值变为"可配置"；通配、回环、私网、公网、特殊地址与未知目标分开。
- 网络、框架、文件、进程、环境信息、敏感及动态代码线索独立记录，不因主分类覆盖其他线索。
- 以 batch.json 为权威任务表，声明路径相对清单自身解析，核对已声明源文件哈希，扫描源目录的伴随文件；缺失/读取失败/路径越界/重复身份均保留结果。
- 将"没有检出线索"命名为 LOW_SIGNAL。
- 记录分类器、输入清单、源文件身份；输出采用独占创建，防止覆盖历史分类和冻结输入。

**准入判定**按 [Spec04](specs/tiered-admission-policy.md) 落地为二元结果：

| 结果 | 触发条件 |
|---|---|
| `BLOCKED` / `input_error` | 文件缺失、哈希不符、路径越界、编码错误等输入完整性问题 |
| `BLOCKED` / `public_network_unverified` | 字面公网地址或域名，且批次未配置网络隔离 |
| `BLOCKED` / `real_credential_suspected` | 高置信度真实凭证**格式**命中（占位符不阻断） |
| `ALLOWED` | 以上均未触发 |

`executable` 仍恒为 false；`executionApproved` 自 v2.2 起与 `admissionStatus` 一致，表达"按 Spec04 未落入阻断项"，
**不等于**平台执行许可。批次级隔离开关经 CLI `--network-isolation-configured` 传入，默认关闭，
启用前须先落盘 Spec04 §5.2 的批次授权证据。

详细字段、主分类优先级、兼容代价和验证命令见[分类器规格](specs/safety-classification-and-admission.md)。

## 6. 执行依赖与最小实验

开发与动态验证分开推进：

1. T01 已完成；T03 已恢复 24 条缺失输入，剩余 15 条需索取或重新冻结，随后人工复核分类、冻结目标及真实入口。
2. T02-b/c/d 可按规格在评估仓库开发；工程测试遵循该仓库及本任务的执行约束。T02-a 的现场恢复要先查清当前升级状态、安装包与无活动 job 窗口。
3. 准入条件满足后，用固定无害 capsule 对当前三系统路线复验。只改变评估栈版本，保持输入/oracle 固定；对照须包含预期一致和预期不一致。
4. 选3–5个已审阅、入口完整的真实任务，包含正常与错误路径；成功后再用现有批次链路扩至单次提交≥40，禁止人工逐项触发冒充自动批次。
5. T05 逐项审阅证据，达标后直接完整剥离，再从目标目录的独立发布复验。

成功信号：身份一致、两侧执行可定位、预置差异被检出、证据和清理齐全。失败信号：任一侧未执行/伪输出/身份不符、负向例被容忍、契约漂移、隔离或清理失败。发生环境故障时不进入转换修复，不以增加重试掩盖失败。

## 7. 验收与指标

分类、提交、执行和效果四层分开记录：

- 输入守恒：219 条均有终态；39 条缺失不从既有分母消失（已恢复 24 条，余 15 条）。若另建候选批次，保存与原任务映射。
- 分类效果：47 个合成回归通过，仅证明所列缺陷路径；真实样本无独立标注全集，不报告准确率/召回率。
- 准入效果：未配置隔离时 ALLOWED 178/219（81.3%）；该比例是准入判定结果，不是运行覆盖。
- 双侧覆盖：有匹配身份的两侧实际 execution 证据任务数 / 冻结任务总数。目标编译通过率、双侧完成率与比较结果分别统计。
- 数据质量：原始输出、截断状态、观察限制、适用比较策略、角色清理均留证；不能只凭 job COMPLETED 或 semantic_pass 判通过。
- 自动批次：单次提交≥40后自动进入有证据终态，无无声丢失/重复执行；SUBMISSION_UNKNOWN 不盲重投。
- 75% 为待验证的覆盖目标，不是当前通过事实，也不成为通过风险标签凑数的理由。未达目标要给真实缺口和下一步，不能把小切片通过写成总体通过。

完整判据见[验收与剥离规格](specs/verification-and-extraction.md)。本工程退出不自动宣告业务的全部方向、战术和长代码指标完成。

## 8. 交付范围、迁移与回退

完整系统包含既有 Controller、三系统 Agent、evaluation-core、evaluation-contracts、原生发布/安装/验证工具、依赖锁、发布必需离线材料、脱敏配置、测试和交接文档。保留 apps/packages/infra/tools 原相对结构；分类器及其回归随交付迁出当前仓库。排除 Translator、RAG、模型密钥、原始攻防数据、VM 口令、.git 与现场运行状态。

按规格先复制、生成逐文件哈希清单、独立核验，再切换消费引用；旧部署和来源不可在新系统验证前删除。部署回退使用已核对的原不可变发布与匹配快照，证据追加，不改写原 job。迁移后的独立复验失败时保持旧部署和未完成状态。

## 9. 工作量与停止条件

仅用于排序的粗估：T02-b/c/d 各约0.5–1开发日；T02-e 约1–2开发日，均不含现场等待与三系统回归。环境恢复时长、39项源码恢复、框架依赖和网络隔离取决于外部状态，不能承诺一个下午完成。分类器 HTTP/Docker 不计入估时。

不满足发布身份、实际入口、隔离/数据边界或清理条件时停止对应执行项，继续静态开发与文档工作。当前动态验收仍受三 runner 契约不匹配阻断，完整剥离尚未发生。

## 10. 转换测试的启动条件

本机不执行样本。转换测试由用户在**另行批准的隔离环境**中启动，启动前须同时满足：

1. 39 条缺失输入已处置（**24 条已恢复并校验哈希**，余 15 条明确重新冻结或索取）。
2. 三 runner 契约身份一致且实际隔离证据已落盘，`batch-authorization.json` 已生成。
3. T04-a 固定无害对照通过；T04-b 真实小切片双侧证据齐全。
4. 用户明确批准。

未同时满足时保持阻断，不以分类结果或准入比例代替上述条件。
