## 2. 推荐开发顺序

```
今晚 Agent 路径：
T01-d-agent 分类准入消费 + T03-b 任务审阅 + T03-c/d 真实隔离/授权记录
                                  + T02-a 已部署健康基线
                                            ↓
                               T04-a → T04-b（3–5项）→ T04-c（≥40项）

后续平台路径：T01-d 平台强制消费与拒收验收 → 完整平台接入
交付路径：适用 T04 证据 → T05-a → T05-b → T05-c
```

**当前可并行推进**：T01-d、T03-a、T03-d（模板与校验部分）、T02-b/c/d。
**受现场阻断**：T03-c。T02-a 的部署与健康验收已完成。
**受前序阻断**：T03-b、T04、T05。

今晚的 T04 不以尚待实施的 T01-d 平台强制消费为前置；Agent 分类准入消费可以承担本工作流的提交核对。已有授权复用，缺具体任务或现场证据则明确待输入，不能把“用户希望开始测验”记成任意样本已隔离或已验收。

T02-e 只在真实任务需要"源失败后取得目标诊断"时进入；不等待所有后续 Collector 才验收当前可覆盖任务。
若任务核心义务需要未实现 Collector，该任务单列阻断，不以其余观察替代。

## 3. 每个开发项的提交材料

- 问题触发、实际代码入口、范围/非目标、候选版本和依赖。
- 实际修改、消费者兼容方案、最小正负测试、证据路径。
- 测试环境与是否执行样本的准确说明；不能把合成静态测试称为功能转换验收。
- 发布/回退影响，尚未完成的验证及停止条件。

不凭估时修改完成状态。**平台代码尚未修改**；当前动态步骤仍受契约不匹配阻断。

## 4. 关键约束（开发时必须遵守）

| 约束 | 来源 |
|---|---|
| 本机不编译、不运行、不连接平台或公网 | [安全边界](../../../../references/framework/safety-boundary.md) §1 |
| 批次授权可复用，但越界行为须先改环境 | 安全边界 §2 |
| 不使用真实凭证/生产数据；敏感行为不自动排除，但须限定于一次性 VM | 安全边界 §3 |
| 只阻断最高危项，其余按 Spec04 §4 允许 | [Spec04](../specs/tiered-admission-policy.md) |
| 准入判定不等于执行许可 | Spec01 §1、Spec04 §5.1 |
