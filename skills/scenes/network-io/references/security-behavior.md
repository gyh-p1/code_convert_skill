# 网络安全行为：转换时不可静默改变的安全语义

本文件在源码是**网络攻防相关代码**、且转换可能影响可观察安全行为时，与 [网络 I/O 场景](../SKILL.md) 共同按需加载。它讲的是**保持源程序原有的安全姿态**，不提供攻击方法、也不新增任何攻防能力。它是静态规则与风险说明，不证明转换后的代码安全或行为等价。

## 通用原则

- 转换默认保持"至少同等严格"：源码里的任何校验、边界检查、大小/数量上限、超时，在目标代码中不得变松或消失；无法保持时显式标注为待确认/未映射，不静默降级。
- 安全相关差异优先从两个来源排查：**跨 OS 平台差异**和**不可信输入解析**。
- 不因"现代化/可读性/更像目标语言"改写校验逻辑、比较方式、解码顺序或失败路径。

## 1. 路径规范化与目录穿越（跨 OS 高危）

处理来自网络的路径/文件名时最易在跨 OS 转换中被削弱。源在一个平台上的穿越防护，换平台后可能失效：

| 维度 | POSIX/Linux | Windows | 转换必须处理 |
|---|---|---|---|
| 分隔符 | 仅 `/` | `\` 与 `/` 都接受 | 只过滤 `/../` 的检查在 Windows 被 `\..\` 绕过 |
| 大小写 | 敏感 | 默认不敏感 | 大小写敏感的黑/白名单在 Windows 失效 |
| 特殊名 | 无 | 设备名 `CON`/`NUL`/`PRN`/`AUX`/`COM1`/`LPT1`、8.3 短名、尾部点/空格被剥离、备用数据流 `file:stream`、UNC `\\host\share`、`\\?\` 前缀 | 这些在 POSIX 源码里无对应，转 Windows 须补进检查 |

- **应保留**：先规范化再校验、拒绝穿越序列、限制在根目录内的顺序与严格度；使用平台的规范化（POSIX `realpath`、Windows `GetFullPathName`/`PathCchCanonicalize`）时确认其行为差异。
- **常见误改**：把 POSIX 的字符串前缀检查原样搬到 Windows；规范化与校验顺序被调换，导致校验发生在解码/规范化之前。
- 依据：[CWE-22 路径穿越](https://cwe.mitre.org/data/definitions/22.html)、[Windows 文件命名规则](https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file)。

## 2. 不可信输入的长度与边界解析

对攻击者可控的网络字节（长度字段、帧、头部）解析时，类型和边界最易在转换中被改坏：

- **应保留**：长度/偏移的溢出与截断检查、有符号/无符号约定、缓冲区边界、嵌入 NUL 的处理。二进制缓冲区不能当 C 字符串（会在首个 NUL 截断）。
- **跨类型风险**：`size_t` 与 Windows `recv` 的有符号 `int` 长度之间转换可能溢出/截断（见 [POSIX ↔ Winsock](../../../systems/posix-winsock/SKILL.md)）；`Content-Length`、chunk 大小等字段换类型后可能回绕。
- **常见误改**：一次 `recv` 当成一条完整消息（见网络场景）；去掉源码里的长度上限；把无符号长度比较改成有符号。
- 依据：[CWE-190 整数溢出](https://cwe.mitre.org/data/definitions/190.html)、[CWE-125 越界读](https://cwe.mitre.org/data/definitions/125.html)、[CWE-787 越界写](https://cwe.mitre.org/data/definitions/787.html)。

## 3. 校验与认证逻辑必须存活

- **返回值检查不得丢失**：证书验证、签名/HMAC 校验、认证函数的返回值若被忽略或分支被删，等于静默关闭校验。保留 `if (verify(...) != OK) 失败;` 这类分支及其失败路径。
- **恒定时间比较**：源码用恒定时间方式比较密钥/令牌/摘要时，不得为"可读性"换成 `memcmp`/`strcmp`/`==`（引入计时侧信道）。跨平台无标准可移植的恒定时间比较，须保留原实现或标注风险。
- **不改顺序/不穿透**：不调换 check-then-use，不让失败路径穿透到成功分支。
- 依据：[CWE-208 可观察计时差异](https://cwe.mitre.org/data/definitions/208.html)、[CWE-295 证书校验不当](https://cwe.mitre.org/data/definitions/295.html)。

## 4. 资源上限与抗 DoS 行为

- 读/写超时、请求与头部大小上限、连接/线程数上限、解析递归或循环深度限制，都是 DoS 防御。转换必须保留；删除即引入源程序原本没有的 DoS 面。
- 超时的跨 OS 单位/类型差异（`timeval` vs `DWORD` 毫秒）见 [POSIX ↔ Winsock](../../../systems/posix-winsock/SKILL.md)，换算错误会静默改变超时值。
- 依据：[CWE-400 不受控资源消耗](https://cwe.mitre.org/data/definitions/400.html)。

## 5. 解码与规范化顺序

- URL 百分号解码、Unicode 规范化、双重解码：`decode-then-validate` 与 `validate-then-decode` 的安全性不同，原样保留源码的顺序。
- 转 Windows 时，路径 API 可能追加一层规范化；须核对是否因此引入二次解码或绕过原校验。
- 依据：[RFC 3986（URI）](https://www.rfc-editor.org/rfc/rfc3986)、[CWE-22](https://cwe.mitre.org/data/definitions/22.html)。

## 6. 不增不减能力

呼应网络场景的底线：不新增监听/外联端点、不把 loopback 绑定放宽到全接口、不新增密钥/令牌/明文日志、不为便利关闭校验、不删除源码已有的访问控制。转换是平移安全姿态，不是重新设计。

## 未知处理

缺少源平台、目标文件系统、协议或信任边界前提时，把安全假设标为待确认，并按**最严格**的合理解释保留，不猜测放宽。交付说明中列出未确认的安全假设。

## 依据与边界

以上 CWE 与规范链接是**分类与风险参考**，用于识别不可静默改动的安全语义，不是对具体转换结果安全性或等价性的验证记录。目标平台/版本具体行为须核对对应官方文档；本文件不授权运行样本或连接真实目标。
