# 长单文件转换工作流

仅用于**单文件转换**；片段任务不需要整文件盘点。语言方向 Skill 决定语言映射，实际场景 Skill 决定要保留的行为，系统方向 Skill（若存在）决定平台差异；本 Skill 只负责组织全文件分析、转换和收尾。计划中的 700 个 LF 归一化物理源代码行是项目试验上限，不代表此流程已通过该规模验证。试验另记录有效 LOC 与 token/context 规模；行数不能替代结构复杂度判断。

## 0. 准入与边界

- 先形成源码画像：任务模式、source/target 语言与系统、架构/ABI、编译器/标准、条件编译分支、真实场景标签，以及 ATT&CK tactic/technique（无证据时记录 `none`）。多平台源文件必须明确本次选用的源分支和目标分支。关键条件缺失且会改变方案时先询问或明确待确认假设。
- 按源码画像选择语言、场景、系统和长文件 Skill；ATT&CK 索引仅帮助核对分类/覆盖，不根据战术反推 API 或隐藏行为。列出每个 Skill 对应的事实和覆盖缺口。
- 长文件只要受限于上下文，就不要假装已完整阅读。用可用的文件读取能力分区检查；记录已覆盖范围和未读范围。无法建立全文件地图时，先请求拆分、补文件或确认允许的分段策略。
- 遵守项目安全边界。读取代码不等于授权执行；不能为了“验证”而运行未知样本、连接真实网络或触发外部副作用。

## 1. 转换前建立全文件地图

先分析源文件，再生成目标文件。建立一份紧凑的工作清单，至少包含：

| 清单 | 记录内容 |
|---|---|
| 任务标签 | 源/目标语言与系统、任务模式、按证据选择的场景、ATT&CK 分类或 `none` |
| 文件轮廓 | 编译条件、include/import、宏、类型、全局/静态变量、常量和入口点 |
| 符号与调用 | 函数/方法签名、定义位置、调用关系、外部符号、回调、条件编译分支 |
| 状态与所有权 | 共享状态读写、对象/资源创建与释放、别名、锁/句柄及生命周期 |
| 可观察行为 | 输入输出、返回值、错误路径、文件/网络/进程副作用、时序、退出与清理 |
| 环境前提 | 平台 API、OS 差异、ABI、架构、字符编码、构建宏、第三方依赖 |

事实只从用户提供的源码、说明和已加载的适用 Skill 中提取；未知内容标为未知，不根据函数名或 ATT&CK 标签推断隐藏行为。将每项关键规则关联到相关符号/函数，方便转换后核对。

## 2. 规划语义分段

- 优先以完整类型、完整函数或紧密相关的函数组为转换单元；不按固定行数盲切，不把函数体、条件分支、宏或资源清理路径从中间截断。
- 分段前确定依赖顺序和跨段契约：共享类型/常量/宏、符号名与签名、全局状态、回调约定、错误表示、所有权和调用先后。
- 每个工作单元记录输入范围、依赖、预期输出符号和已完成状态。未转换、部分转换、待合并和已核对要区分；不得凭摘要声称覆盖了未读源码。
- 若上下文不足以同时保持源段、依赖地图和目标段，缩小单元或暂停并请求确认，不牺牲跨段一致性换取表面完成。

## 3. 逐单元转换

- 按依赖顺序转换，每个单元都遵循匹配的语言、场景和系统 Skill；不在工作单元中重复定义共享声明。
- 默认做实现目标语言所必需的最小改动。保持公开接口、控制流、状态读写顺序、错误/返回值、资源生命周期和副作用；重构或降级必须有明确前提和用户授权。
- 记录无法映射、依赖缺失、假设和有意差异，并定位到涉及的函数/符号。不要在最后才汇总无法对应的内容。
- 源片段语义未定义、平台行为未明或外部契约缺失时，保留差异并说明，不制造虚假的唯一等价实现。

## 4. 合并与全文件核对

生成单文件结果后，对照转换前画像和源文件地图逐项检查：

1. 源文件中应迁移的类型、声明、定义、宏、分支和入口是否遗漏或重复；
2. 目标声明/定义、调用点、名称、参数、返回值和可见性是否一致；
3. 全局/静态状态的读写、调用顺序、条件分支、错误返回和退出清理是否偏离；
4. 跨段引用、回调、资源所有权及平台条件是否仍闭合；
5. 相关场景规则要求保留的输入输出、协议/字节、文件/进程副作用是否有对应实现；
6. 每项未实现、降级或不确定的源行为是否在交付说明中指出。

模型转换后可按 [C → C++ Skill](../../directions/c-to-cpp/SKILL.md) 做自评与 repair 预判；这只是非独立预检，用于发现疑点，不作语法正确性结论。后续进入[转换—自审—第三方评估闭环](../../../references/conversion-evaluation-loop.md)，由 Agent 按受限自修、预检门槛、第三方诊断分流与失败停止条件调度。按用户约定，语法结论由第三方评估机构在匹配工具链下编译回填；只有在获批且适用的评估环境中执行。语法结果与行为 oracle 结果分别报告；编译通过不代表行为等价。

## 5. 交付

提供完整目标文件或明确指出未完成部分。长单文件同时保存 `source-analysis.md`（源/目标配置、证据化标签、ATT&CK 判断、所选 Skill、源码地图与未决项），便于复核 Skill 选择。简要报告：实际完成范围、需要确认的假设、未映射/降级行为、语法与行为检查分别是否执行及结果。未运行或无 oracle 时写明“未验证/无法判断”，不宣称功能等价。源文件较大时可附函数/符号覆盖摘要，但不要用摘要替代用户要求的目标文件。
